# Two provider kinds: model and harness

The user has Claude and Codex subscriptions and no API keys. Anthropic does not permit third-party programs to call its API with subscription credentials, but it does permit a user to sign in to the unmodified Claude Code binary. OpenAI documents the Codex app server for third-party clients. So the Provider interface admits two kinds. A model provider calls a model API, and Helyx runs the turn and the tools. A harness provider drives an external agent program over stdio and records what it did. Both write into the same transcript and emit the same events.

## Consequences

- During a harness turn, Helyx tools are not visible to the model. The harness uses its own tools. Exposing Helyx tools to a harness needs an MCP server and is a later change.
- The first model provider speaks the OpenAI wire format. There is no Anthropic Messages implementation, because the user has no API key to test it with.

## Revision

2026-09-26: The two provider kinds are now one flag named by behaviour, `turn/0`: `:local` (the default) or `:external`. An external turn runs the whole turn and its own tools in one provider call. The session records the tool results and does not run the tools. The provider keeps its own conversation state, which the session resumes by id. The stream runs under the hands. A steer aborts the turn. Claude Code and Codex have external turns. The reasons of this decision do not change. The product term "harness provider" stays and names a provider with an external turn (#123).

2026-09-30 (#265, approved by the owner): a provider is one of two kinds. An API provider has a local turn: Helyx runs the loop and the tools, and the provider implements `stream/3` (today the OpenAI-compatible provider). A harness provider is connected: it exports `harness_init/3` and the harness callbacks of ADR 0007 (today Claude Code and Codex). The export of `harness_init/3` is the only signal. The `turn/0` callback, the per-turn `:external` mode, and the start error `{:bad_provider_turn, id}` are gone, and `stream/3` is optional for a connected provider. No bundled provider used the per-turn mode; only test fakes did. A future harness program with no persistent-process mode, one that cannot keep a process across turns, would need the per-turn path again: a new decision that brings back a stream of the whole turn under the hands and a steer that aborts the turn.

2026-10-02 (#300, `docs/features/one-provider-path.md`): one provider kind. Every provider implements `init/3`, `request/3`, and `info/2`, and runs in a provider process for the session (ADR 0007). An API provider implements `stream/3` and adds `use Helyx.Provider.Loop`, a Core adapter that runs each model call in a model Task and sends the tool calls to Core as tool requests, one at a time, in call order. The local turn path is gone: `stream/3` is not a callback of `Helyx.Provider`, and the session has no turn mode. Two things that clients see change, under contract version 2: every call of a message gets its `tool_execution_start` at the `message_end`, and a snapshot lists every call with no result as running. The ADR 0006 revision of 2026-10-03 (#404) removes the contract version and the snapshot `running` from the contract, and the TUI stops reading `tool_execution_start`. A steer in the last model call of a turn continues the same turn. The product terms "model provider" and "harness provider" stay and name what the provider drives.

2026-10-17 (#651, decided by the owner; `docs/features/provider-parity.md`): a provider is a provider. A product picks a model ref, and the provider kind does not change what the product gets: a harness provider gives the model the system prompt of the turn's context, which replaces the harness prompt, exactly the session's tools, with the harness's own tools off, and none of the user's own harness config (instructions, hooks, skills, plugins, MCP servers), with the login of the subscription kept. A difference is allowed only as a named trade-off or a named limit in the list below, with its reason. Any other difference is a bug. The research is in `docs/research/provider-parity.md`; neither program gives full isolation, so each residual is a named limit, and both providers stay bundled with their limits.

| Item | API provider | Harness provider | Class |
| --- | --- | --- | --- |
| Compaction | Helyx Compaction (#490, planned; `Helyx.Provider.Loop` answers `:unsupported` today) | the harness's own (`docs/features/harness-compaction.md`) | trade-off: the harness compacts its own history better |
| Context per call | built again before each model call | built at the turn start; the harness runs its own loop. No hook before each model call is known: Claude's hook events name no model call (research note) | limit of the integration |
| Turns that the program starts | none | `origin: :provider` | limit; exact tools remove the main cause (native background tasks and sub-agents) |
| History | the transcript only | the program keeps its own copy; a fresh program gets a replay capped at 400,000 bytes, without signed thinking | fidelity limit |
| Usage | one entry for each model call | can sum several calls in one message (`docs/features/usage-and-limits.md`) | reporting limit |
| Stop reason | from the model | Codex reports `:end_turn` for every end without an error | reporting limit |
| Steer timing | taken before the next call | Claude: a queued user line; Codex: `turn/steer` | timing limit; at most once on both |
| Abort | Helyx releases the calls | also: Codex stops the program when an open native command outlives the interrupt | lifecycle limit; exact tools remove most native commands |
| First turn start | the stream starts | the Claude launch or the Codex thread open runs inside the 2,000 ms reply bound of the turn | limit: a slow network can fail the first Codex turn with `:provider_timeout` |
| Prompt change | the next call has the new prompt | the program ends at the turn start, once per turn, and a new one resumes the harness session when the old one has exited | lifecycle limit: an old program that does not exit within 1,000 ms after the end of its input, for example one that still runs a program turn, fails the turn with `:program_not_ended` |
| Claude prompt and context | the product prompt only | the program adds a billing header and its identity line before the product prompt, the account email in the first user message, and an environment section (working directory, git state, platform, shell, OS, model, date) | limit: no flag removes them |
| Codex prompt and context | the product prompt only | the program adds the user's `~/.codex/AGENTS.md` and an environment context (working directory, shell, date, timezone) | limit: no `codex app-server` flag removes them without the user's login |
| Codex tools | exactly the session's tools | also `apply_patch`, `request_user_input`, the `multi_agent_v1__*` tools, the MCP resource tools, and the tools of the user's MCP servers; the session's tools are nested under the program's `exec` tool | limit: no flag removes them; a user MCP tool that starts a process gets no Helyx abort, output bound, or tool event |
| Isolation | none needed | Claude keeps managed (policy) settings; Codex keeps the user's MCP servers and `~/.codex/AGENTS.md` | limit |
