# 2026-10-04: TUI footer (#484)

## Done

- `Helyx.TUI.Footer` owns the footer: two dim rows, no key hints. Row 1 is the directory, with the home as `~`, and the git branch. Row 2 is the model, the run state, the queue counts only when not zero, and `scrolled`; a reject reason comes first, in red. The spinner frames and the tick interval moved there from `Helyx.TUI`, so `tui.ex` went from 399 to 376 lines.
- The branch comes from the files, not from a `git` process: the nearest `.git` at or above the directory, a directory or a `gitdir:` file. Each read takes at most 4,096 bytes and only of a regular file, so a FIFO cannot block. The TUI reads it at mount and after each `turn_end`.
- `Helyx.TUI.run/1` takes `:cwd`; `CodingAgent` passes the session directory, because the snapshot has no cwd.
- Home and End with an empty composer go to the oldest and the newest output; with text they move the cursor. Ctrl+End is gone. `Composer.empty?/1` is new.
- The key list is in `apps/coding_agent/README.md`.

## Broke

- The footer has two rows, so the scrollback tests run at 24 by 10 and the small-terminal heights moved by one row.
- Review found that a hand-written `HEAD` could show any name, also one that looks like a second location. The footer now shows a branch only when the name passes the rules of `git check-ref-format --branch`, and it trims only what git trims.

## Decisions

- Row 2 is left-aligned with the model first, as the ticket lists it; the mock-up puts the model on the right next to the usage of #488.
- `scrolled` stays on row 2: it is state, not a key hint, and the feature doc requires it.
- A file read, not `git branch --show-current`: no external program, and no wait without a bound in the TUI process.

## Open

- The snapshot has no cwd, so a remote client cannot show the session directory. Adding `cwd` to `Helyx.Session.Snapshot` is a change of the client contract (ADR 0006) and needs a decision.
- macOS Terminal.app may use Home and End to scroll its own buffer. A manual check is open.
- Round 3 of the review found two defects after the round limit (see the review record): a `HEAD` that names `HEAD` shows `(HEAD)`, and the trim at the end of `HEAD` also removes `\v`, `\f`, and the byte 0x85, which git keeps. The fixes are one line each.
