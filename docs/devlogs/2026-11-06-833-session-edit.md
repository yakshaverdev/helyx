# 2026-11-06: session delete and message removal (#833)

Done: `Helyx.Sessions.delete/2` and `remove_message/3` (`docs/features/session-edit.md`). Both hold the writer lock, refuse a running session with `:running`, and change the file only through commands of the perl process that holds the `flock` (a new rename command `m`). A removal rewrites the file without the group of the message (an assistant message and its tool results), relinks the chain, the `last_id` of a compaction or summary, and the `first_kept_id` of a summary. The cancellable killer of the session open moved to `Helyx.Session.Killer`, so that a removal uses it too.

Broke on the way (review, `docs/reviews/2026-11-06-833-session-edit.md`): the read of a resume appended a newline outside a lock command; the delete order lost the session file on a failed copy remove; a `:timeout` could follow a sent rename; a symlinked file kept its target.

Open after three rounds: a Core stop during a removal can give `:timeout` after the rename ran, and the temporary copy has the umask mode during the copy. Both have a fix direction in the review record.

Later the same day: both fixed on the orchestrator's decision. `:timeout` comes only from the killer's own kill (it ends with `:fired`); any other end of the edit Task with no result is `:unknown`. The copy is 0600 before its first byte. The Task machinery moved from `Helyx.Sessions` to `Edit.run/3` for the file limit.
