# 2026-11-06: the Hook interface (#879)

Follow-up 1 of ADR 0013: `Helyx.Hook` with `before_tool` and `after_tool`, built by the ticket worker.

Done:

- `Helyx.Hook` (mode `:multi`), its Core start check (`{:no_hook_point, module}`, `{:invalid_hook_limit, module}`), and `Helyx.Core.hooks/1`.
- The chain of a Helyx tool call in the call Task (`Helyx.Session.Hands.Chain`), each hook in a hands Task of its own (`Helyx.Session.Hands.Hooks`) with hold, release, a self-armed kill at its limit, and the refusal after an unconfirmed release.
- `Helyx.Tool.ask/1` and `Helyx.Hook.ask/1` call the session, which checks the caller against the record of each call and hook Task that the hands send at its start (owner decision after the first commit: the session checks the caller, ADR 0013 §3; an ask never waits for the hands).
- The `hook` entry of the session file (`Helyx.Session.HookEntry`) and its reader, which drops a bad one.
- `docs/features/hooks.md`, AGENTS.md, README.

Broke on the way: the first limit timer ran through the hands mailbox, and the hands could take a late answer while they released another Task; a call Task that died left its hook running; a `{:hook}` request of a killed call Task crashed the hands. All fixed in review round 1 (`docs/reviews/2026-11-06-hooks-879.md`).

Decisions the ADR left open, set in the feature doc: the error name `{:no_hook_point, module}`; one monitor for each call and hook Task; the status of a replaced start answer is kept, and `Background.lost/1` takes an error start answer.

Next: #880 (before_settle), #881 (harness approvals), #882 (approval gate), #883 (command hook).

The 23 TUI test failures in `plugins/bundled` fail on master too in this home folder (a skills folder of the user fills the skill list); not from this change.

Third commit (owner review): the go of a call or hook Task now comes from the session after it handled the Task's record, so the record precedes any ask by the order of one process; the hands send only the record. A background run waits for a second go after its start answer, so its later ask comes after the session dropped its record. Master's `lib/helyx/session/file.ex` was at 400 lines (the system prompt entry, #553), so the hook entry is written through the plain `append/2` of the file, now public with `@doc false`, and not through a typed function; `Helyx.Session.HookEntry` owns the shape of the entry.
