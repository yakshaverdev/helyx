# 2026-11-06: the Hook interface (#879)

Follow-up 1 of ADR 0013: `Helyx.Hook` with `before_tool` and `after_tool`, built by the ticket worker.

Done:

- `Helyx.Hook` (mode `:multi`), its Core start check (`{:no_hook_point, module}`, `{:invalid_hook_limit, module}`), and `Helyx.Core.hooks/1`.
- The chain of a Helyx tool call in the call Task (`Helyx.Session.Hands.Chain`), each hook in a hands Task of its own (`Helyx.Session.Hands.Hooks`) with hold, release, a self-armed kill at its limit, and the refusal after an unconfirmed release.
- `Helyx.Tool.ask/1` and `Helyx.Hook.ask/1` go through the hands, which check the caller; the session monitors the asking Task.
- The `hook` entry of the session file (`Helyx.Session.HookEntry`) and its reader, which drops a bad one.
- `docs/features/hooks.md`, AGENTS.md, README.

Broke on the way: the first limit timer ran through the hands mailbox, and the hands could take a late answer while they released another Task; a call Task that died left its hook running; a `{:hook}` request of a killed call Task crashed the hands. All fixed in review round 1 (`docs/reviews/2026-11-06-hooks-879.md`).

Decisions the ADR left open, set in the feature doc: the error name `{:no_hook_point, module}`; the caller check in the hands, not the session; one monitor per ask; the status of a replaced start answer is kept, and `Background.lost/1` takes an error start answer.
