# 2026-11-07: the command hook (#883)

## Done

- `Helyx.Hook.Command`, a bundled hook plugin on `before_tool` and `after_tool` (ADR 0013 §8): config under `:command_hook`, the call as JSON on standard input in the Claude Code field names, exit 0 / 2 / other, the JSON answer shapes, and a bound of 262,144 bytes on each of standard output and standard error.
- The watchdog merges standard error into its port, so a small perl relay (`plugins/bundled/lib/helyx/hook/command/relay.pl`) runs the command with two pipes and writes frames. Core, the hands, and the watchdog are unchanged.
- Feature doc `docs/features/command-hook.md`; research note `docs/research/claude-code-hooks.md` (the field names, observed in the Claude Code 2.1.319 binary).

## Open

- `before_settle` (the `Stop` input, exit 2 as `{:continue, stderr}`) waits for #880, which adds the point.
- The ticket named a triage comment; #883 has no comment. The decisions come from ADR 0013 and the owner comments on #563.
- Round 2 left four items open; the owner decided them the same day, and a second `/ship` cycle built them: a `nil` key is a broken config (`limit_ms: nil` stops the Core start), a deny keeps the `decision: "block"` reason, the answer is what the command wrote before it exited (stated, with the reason), and the relay ignores HUP and sends a TERM or HUP that was pending at its fork on to the command. Tests check the release by process group and cover an aborted turn.
- Codex review round 1 found that the relay died at a release's TERM and denied the command its grace; fixed in round 1, with a test that fails without the fix.
- Two runs stopped at the usage limit of the model account and were resumed.

## 2026-11-08: before_settle

- #880 merged the `before_settle` point. Its input had no folder, so the command had nowhere to run; the orchestrator decided that Core adds `cwd`, the session's folder, to the input (`Helyx.Session.Server.Settle`, ADR 0013 §2 update, `docs/features/hooks.md`, `docs/features/before-settle.md`).
- `Helyx.Hook.Command.before_settle/1`: a `Stop` input, exit 2 as `{:continue, stderr}`, `decision: "block"` with `reason` as a continue, `continue: false` as a settle; its config entry has no `tools`.
- Found while testing: the Helyx process of this session runs with SIGHUP ignored, which every child inherits, and the HUP tests of the relay failed. The relay now sets TERM and HUP to their defaults at its start, as libuv does for a child.
- Review found that the answer reader read a repeated JSON key (first value kept) and white space that JavaScript's `trim()` drops before `{` differently from Claude Code; both now fail closed or read as Claude Code does (`Helyx.JSON.decode/2` with `:unique_keys`, `@js_space`).
- Open: a multibyte white-space character split by the 262,144-byte output cut right before `{` reads as plain text (allow, settle). It was there before this change too; the review record has the fix to make.
