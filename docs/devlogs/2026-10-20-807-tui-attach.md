# 2026-10-20: helyx attaches (tui-attach slice 3, #807)

## Done

- `helyx` without `-p` tests the data folder with `CodingAgent.Attach.connect/1`. With a server, `CodingAgent.attach/2` opens the connection, starts or resumes the session over the wire, and runs the TUI on it; the quit closes the connection and aborts nothing. With no server, it runs in the node as before. The lines of the attach end `helyx` with exit 1.
- `Helyx.TUI.Link` is the session of the TUI: a `Helyx.Session` or a session of the server. Every call of the TUI on its session goes through it.
- `Helyx.TUI.Wire.Connection` gets `take/1` (the TUI process starts in `start_link`, after the connection exists, so it takes it at its mount) and `stop/2`, and refuses a replay in reply to a subscribe with no `after`.
- `--session` over the wire finds the file of the id on the client (`Scan.find/2`), as the node does: the first version asked the server with `sessions.live` and printed the raw `start_failed` text of the server for a bad id (review round 1).
- The decisions that the ticket left open are in `docs/features/tui-attach.md`, slice 3.

## Broke

- With no perl on the PATH, `helyx` now prints the line of the lock test before the tool check of a start in the node. The CLI test of #765 checks the order of the node through `CodingAgent.run/1`.
- Review round 1 found that a paste over 25 MiB closed the connection (4413), that a refused stop or abort over the wire was silent, and that a cwd that is not UTF-8 crashed the connection process: `docs/reviews/2026-10-20-807-tui-attach.md`.
- A run of the TUI tests failed once in `wire_test.exs` ("a text of the frame bound joins from fragments ..."): the fake server writes after the client closed. Not changed here; it passed alone three times.
