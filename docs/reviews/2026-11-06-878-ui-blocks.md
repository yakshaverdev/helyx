## Accepted holes

- A second run of a call, a reused call id (#369), replaces the held result blocks of the first, so the result message that joins can carry the blocks of the second run (owner decision of 2026-11-07).
- The blocks of a call whose request came before its tool call and whose call never streams stay until the turn ends, within the 72 of the turn: the blocks that its Task showed, which the snapshot and the clients fold from the same events, and the blocks of its result in `held_results`, which no client sees.
- After a request past the 256 Helyx call ids of a turn, that call shows no blocks, and the provider's own blocks that name a call are dropped for the rest of the turn; a block with call id nil still shows.
- `:ui_block` events have no rate cap; the credits and the transport bound the bytes queued to a subscriber (ADR 0011, "Bounds").
- The end of a background run drops the blocks of its return: it is a user message, not a tool result.
- The local run of `plugins/bundled/test/helyx/tui_test.exs` and of three tests of `apps/coding_agent/test/coding_agent/print_test.exs` fails on this machine because of the skills installed in the home folder (a "skills were left out" notice); precommit runs on the precommit host.
