# Review: the environment of the harness program (#751)

Scope: the working tree against the branch base `751db05d`. Files: `plugins/bundled/lib/helyx/harness_io.ex`, `plugins/bundled/lib/helyx/watchdog.ex`, the Claude Code and Codex provider modules (`claude_code.ex`, `claude_code/{program,state}.ex`, `codex.ex`, `codex/state.ex`), the new tests `claude_code/env_test.exs` and `codex/env_test.exs`, `.credo.exs`, the feature doc `docs/features/harness-no-state.md`, and `docs/features/long-lived-harness.md`.

Invariant: every entry of the provider option `env` (given through the session option `:provider_opts`) reaches every launch of the harness program under the same name with the UTF-8 bytes of its value, on top of the inherited environment, or `init/3` fails with `{:invalid_option, :env}` and nothing runs. With the default Logger config, no value of it is in a log line, an event, an error, or a crash report.

## Probes of the author

No probe printed an environment value; each compared in the program and printed `match` or `nomatch`.

- `Port.open/2` with `env`: a value with `é` arrives as UTF-8; a name with `=` or NUL, a value with NUL, and a binary name raise `ArgumentError`; an empty name does not raise; a value of 2,000,000 bytes gives the exit status 7 (`E2BIG`) with no output.
- `/bin/sh -c 'exec "$0" "$@"'` on macOS passes the names `A-B`, `A.B`, `1A`, and `a_b` to perl.
- After the fix of round 1: `elixir --erl +fnl` and `+fnu`, `Helyx.HarnessIO.env/1` with the value `€é`, then the port: the program gets the UTF-8 bytes in both.

## Orchestrator decision 2 (2026-10-19): change the invariant, not the mechanism

1. New invariant: each entry of `env` is set on every launch of the harness program, on top of the inherited environment. `init/3` refuses, with `{:invalid_option, :env}`, the names that the launch shell or the OS is known to set itself (`@shell_names`). A shell or an OS can set other names of its own; that is a stated hole. The tested use case is a state folder variable (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`), and it reaches the program unchanged.
2. The eight names of round 3 join the list: `XPC_FLAGS`, `XPC_SERVICE_NAME`, `BASHPID`, `BASH_ARGV0`, `SRANDOM`, `BASH_MONOSECONDS`, `EPOCHSECONDS`, `EPOCHREALTIME`.
3. The feature doc and the comment of `HarnessIO.env/1` state the invariant, the hole, and the source of the list. No moduledoc states the guarantee: `Helyx.HarnessIO` is `@moduledoc false`.
4. One reduced round past the limits of `/ship`, with the hole in every brief.

Fix: 33 names in `@shell_names` and in the list of the test "each name that the shell or the OS sets itself fails the init"; the feature doc, "The invariant", "The check", the Bounds row, and "Out of scope"; the bullet of `long-lived-harness.md`.
