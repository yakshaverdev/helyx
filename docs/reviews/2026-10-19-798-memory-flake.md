# Review: the recall limit of the memory failure tests (#798)

Scope: the working tree against the branch base `f2279ecb`. File: `test/helyx/session/memory_test.exs`. Test-only.

Invariant: in `test/helyx/session/memory_test.exs`, only the hang case runs with the recall limit of 100 ms. The error and raise cases, and the error case of the two-call test, run with the limit `@load_recall_ms` (5,000 ms), the margin for load. A recall Task that is slow to run under load therefore cannot change their logged reason to `:timeout` or lose its `{:recall, ...}` message. The assertions do not change.

## Decision

- Two tests, not two Cores in one test: `start_core/1` registers the test process as the memory controller of its Core, and a process has only one registered name. The four assertions moved without change into `assert_failed/3`.
- `@load_recall_ms` is a new attribute, not `@load_ms`: the comment of `@load_ms` is about a drain, and the other test files name one `@load_` attribute for each purpose.
- The test "a failed recall in a turn with two calls gives one notice" also moved from 100 ms to `@load_recall_ms`. The ticket does not name it. Its "fail" recall needs no short limit, and under load a kill at 100 ms before the plugin runs takes its `{:recall, ...}` message, which the test waits for.

## Proof (author)

- Red: with a 150 ms sleep before the raise in `test/support/memory.ex`, the old test failed with the ticket's error (`left: "...memory recall failed: :timeout\n"`, `right: "memory recall failed: RuntimeError\n"`). With the same sleep, the new tests of the `recall` describe passed (12 tests, 0 failures).
- Acceptance mutation: with a 5,100 ms sleep before the raise, the new test at line 119 failed with the same `:timeout` against `RuntimeError` error. The support file is restored.
- Repeat: the three changed tests with `--repeat-until-failure 50`: 51 runs of `3 tests, 0 failures`, on the machine with the other worktrees running.

## Simplify

One agent. No edits. Rejected: reuse of `@load_ms` (other meaning), a default limit in `start_core/1` (other tests need the Core default), a rename of `assert_failed/3` (it pairs with `@failed`).
