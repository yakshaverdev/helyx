### The freeze of the precommit host

Two precommit runs of this branch froze the shared precommit host for 36 minutes each: a `/usr/bin/kill -STOP 0` stopped every process of the process group of the run, so the whole `mix precommit` pipeline (orchestrator report). The cause, read in the OTP 28 source: `spawn_start` (`erts/emulator/sys/unix/sys_drivers.c`) creates a spawned port with the os pid 0 (`create_driver_data(..., 0, ...)` writes `prt->os_pid`), and the pid is set only when `erl_child_setup` answers with its `Go` message (`erl_drv_set_os_pid`). `port_info(Port, os_pid)` gives `undefined` only for a negative pid (`erl_bif_info.c`), so in that window it gives `{os_pid, 0}`. The test "a removal whose lock holder ends" found the port of the edit Task through `Port.list/0` as soon as it was connected, before that answer, read the pid 0, and sent `kill -STOP 0`. A process that opens a port gets it back only after the answer, so the other tests, which read the pid of a port after its take or its open returned, read the real pid; a loop of 200 such reads on macOS gave only positive pids. The same `kill -STOP 0` stopped a local loop of the test file (it ended at the time limit of the tool), and the 14 stopped perls of the section above were in that stopped group.

Fix: `Helyx.Test.PerlSignal` sends every signal of the tests of the root project. It waits until the port reports a pid over 1, sends only to a positive pid that `ps` shows as the perl whose arguments end with the lock path of the test, and fails the test otherwise, with no signal. A continue in an `on_exit` sends nothing to a pid that is no longer that perl. The users: the new tests, `lock_test.exs` (the stop past the release bound, and two kills), and `Helyx.Test.LostLock`. A test of the helper checks that the pids 0 and -1 and a process that is not the perl of the lock get no signal. A stop of perl stays where the test needs perl to hold its answer: a suspend of the Task cannot hold perl's answer to a command that the Task already sent. Tests of `apps/` and `plugins/` also send signals (for example `harness_epipe_test.exs`); they are not on this branch and this review did not check them.

Reduced round on the guard (spec, failure path; the first two agents of the round ended at the usage limit of the model account and were run again): no reproduced defect. The spec agent confirmed the cause in the OTP 28 source and with a probe (14 of 100 reads of the pid of a port found through `Port.list/0` gave 0). The guard holds for lock paths with spaces, non-ASCII bytes, and relative paths on macOS; a path with a newline is refused, so the test fails with no signal. Not covered: a pid reused between the check and the `kill`. A failing test with perl stopped leaves no stopped perl: the `on_exit` continues it, and the held processes resume when the test process ends. Wording fixed: the comments of `Helyx.Test.PerlSignal`, and an assertion of the test of the guard that did not show what it claimed.
