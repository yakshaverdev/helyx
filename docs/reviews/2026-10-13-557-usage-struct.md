# Review: #557 The usage struct and the serving side

Invariant: every assistant message usage is nil or a `Helyx.Usage` within the struct bound, which `Helyx.Session.Stream.check/1` and `Helyx.Session.File.Codec` enforce. Each provider maps wire values within the wire bound at its boundary. The usage of each `done` covers every model call that the serving side reported since the previous `done` of the same provider process: Claude Code `Meter` sums the `result` lines and takes the cost as the `total_cost_usd` difference from a mark, so the cost of each `done` covers only the model calls since the previous `done` of the same Claude session, including the first `done` after a resume (`Transcript.resume/3` gives the stored sum as the mark); Codex `Items` sums `tokenUsage.last` and keeps the sum over a turn with no `done`; OpenCode maps one usage chunk per call, and `Loop` keeps the usage of a call with no `message_end`.

Accepted: work that a harness session did outside Helyx is counted once, at the first `done` after a resume (owner decision on 1.6). The Codex and OpenCode costs stay nil until #559, so the flag of "Per provider" is not built yet. Codex sub-agent tokens are not counted (known ceiling of the feature doc). A new provider process, or a relaunched Claude Code program, starts a new sum; a relaunch starts a new harness session, so its mark is 0. The OpenCode gateway usage chunk was not recorded: the machine has no OpenCode key.
