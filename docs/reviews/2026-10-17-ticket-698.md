# Review of one context estimate rule (#698)

The change: `Helyx.Session.Totals.context/2`, which builds the `context` field of the snapshot and the context % of the TUI footer, takes the rule of the estimate of `Helyx.Compaction.Summary` with no summary. The last usage with integer `context_tokens` starts the estimate; a usage with nil `context_tokens` adds the bytes of its message and keeps the window and the model; a tool call counts the bytes of its name and of its JSON arguments. The rule is two short functions, one in Core and one in the plugin, and the feature docs name each other.

## Simplify

Four agents (reuse, simplification, efficiency, altitude).

| Finding | Resolution |
|---|---|
| The test replaced the content of the assistant message and built the `"ok"` block twice | appends the call to the content of the helper |
| The magic number `2 + 4` in the test | `byte_size("ok") + byte_size("bash")` |
| `tokens: ... \| nil` in `@type context`, the guard `is_integer(context.tokens)` in `Helyx.TUI.Footer`, and `tokens: int \| null` in the wire doc can no longer be nil | kept: #697, on the same branch, sets `tokens` to nil after a compaction with no `tokens_after` |
| At subscribe, an encode of the arguments of a call before the last usage is discarded | skipped: a fold from the newest message back is more code for a rare cost; the failure-path agent measured 44 ms for 5,000 calls of 8 KB with no usage after them |

## Accepted holes

- Before the first usage with integer `context_tokens`, the footer shows no %, and the trigger reads a quarter of the bytes of the context to send. `Totals` has no system prompt and no ModelContext, so it cannot count the context to send.
- With a summary, the trigger reads a quarter of the bytes of the context to send, and the footer keeps the estimate of the last usage. #697 changes the footer at a compaction.
- The window of the footer is the window of the usage of the estimate; the trigger takes the last window of the same model.
