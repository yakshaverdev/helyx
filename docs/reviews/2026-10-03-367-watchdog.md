# Review: the watchdog keeps its safety lock, without review-only hardening (#367)

Date: 2026-10-03. Base: `origin/master` at the branch point (`b83e08d`). Scope: `plugins/bundled/lib/helyx/watchdog.ex`, `watchdog/watchdog.pl`, `watchdog/group.ex`, the start report part of `tool/bash.ex`, the `{:started, ...}` match and one comment in `harness_io.ex` (not `keep_port/1`), their tests, `docs/features/coding-agent.md`, and `docs/features/tool-resource-release.md`.

## Invariant

`Helyx.Watchdog.start/4` (entry points: the bash tool's `run/2` and `Helyx.HarnessIO.start/5`) never lets a command run before the hands hold its watchdog and its command group. A closed port always ends the command group (TERM, grace, KILL, reap). The open input cap stops a stuck command. `Group.release/4` never signals a group below 2.

Accepted holes, stated in `coding-agent.md`:

- A failed `exec` is an ok bash result with the reason and `Exit code: 127`, as a shell gives.
- A watchdog killed from outside before the go-ahead, or a go-ahead write that finds the port closed, gives an ok result with `Exit code: 137`. No part of the command ran.
- `EPIPE` on the go-ahead write ends the caller through the port link.
- `PERL*` variables of the environment reach the watchdog interpreter.
- perl removed after the caller's check makes `Port.open` raise in the caller.
- A handle below 2 is dropped and not signalled.
