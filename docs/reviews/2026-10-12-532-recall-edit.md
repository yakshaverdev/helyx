# Review: #532 An edit of a recalled prompt survives Up and Down

Invariant: An edit of a recalled prompt is never lost, and a key that only moves the cursor inside the text never changes the text. Up on the first row or Down on the last row (the `edge?/2` row test of recall) of a recalled prompt (`Helyx.TUI.Composer.recall/3`, from `Helyx.TUI.handle_event/2` for plain Up and Down) whose composer text differs from the text that showed for it first ends the recall. On any other row the key only moves the cursor, and the recall stays with its shown text. The new draft is the waiting draft, then the edited text, joined by one new line, with empty texts dropped and no other bytes. Both paste maps merge, and no marker id repeats. The cursor stays on the same character of the edit. Then the key acts on that draft as on any draft: Up recalls again from the newest prompt, and Down past the newest prompt brings the new draft back. A recalled prompt with no edit, or with an edit undone back to the shown text, changes nothing. `Composer.apply/2` for `queue_dropped` uses the same join helper (`draft_parts/2`) and keeps its order: texts, draft, recalled prompt.

Accepted holes: the composer text is unbounded human input (#29). Only one draft is kept: there is no edit for each earlier prompt (out of scope in the ticket). `queue_dropped` still brings back an unedited recalled prompt (the accepted hole of #513).

Decision source: the #513 review record (`docs/reviews/2026-10-12-513-queue-return.md`, round 1, simplify skip), decided by the owner on 2026-10-12. The orchestrator clarified step 2 of the ticket after round 1: an edit ends the recall only when the key is at the edge where Up or Down would recall.

## Round 1 (full)

Skipped: deriving the shown text from `vm` and the cell position (altitude). The view model can change while a prompt is recalled, so a derived text does not prove what showed. Skipped: two extra linear copies on the path where an edit ends the recall (efficiency). They happen once for each edit, and avoiding them needs an edge computation before the write. Reuse found nothing.
