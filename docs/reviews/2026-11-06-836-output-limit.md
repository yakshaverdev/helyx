# 2026-11-06: review of the session start option `:max_output_tokens` (#836)

Invariant: every assistant message of a session started with `:max_output_tokens` is requested with that limit. `Helyx.Session.start/2` and `Helyx.Sessions.start/2` check the value (an integer from 1 to 2,147,483,647) and refuse a provider that cannot apply it with `{:error, {:max_output_tokens_unsupported, id}}` before any file or process exists. `Helyx.Session.set_model/2` refuses such a provider and keeps the model. `Helyx.Provider.Loop` passes the limit to `stream/3`, and a provider option of the same name does not override it. The OpenAI engine puts the limit in the body field that the endpoint option `max_tokens_field` names. Core reads each provider's `max_output_tokens?/0` once, at its own start. Accepted holes, all listed in `docs/features/output-limit.md`: a resume runs with no limit, the summary call gets no limit, the OpenCode Go server may ignore `max_completion_tokens`, the wire has no field, a child session gets no limit, and the harness providers reject the limit.
