## Option 1: the cleaning walk (a new `/ship` run)

The owner chose option 1 (comment on #509, 2026-10-12): one bounded walk puts `:stacktrace` in place of every stacktrace in the reason before Core writes the text. The branch was squashed and rebased on `origin/master` at `02de87b` (#508, #512, #513, #514, #518, #522 and the others). ### Replaced mechanism

1. Old: `crash/1` found an error with its stacktrace by a list of shapes (an exception or a raw error with a frame list, under `:task_exit`, `:provider_init`, `:provider_stop`, `:shutdown`, `:EXIT`, any atom tag, an exit signal, or a call exit), and the text was the message of `Exception.normalize(:error, error, stack)`. A reason in no listed shape was inspected whole, stack included. New: `clean/2` replaces every stacktrace at any depth, then `describe/1` writes the text. `crash/1` stays as an unwrap after the cleaning, for a shorter text; it matches `{error, :stacktrace}` and is no longer a safety step.
2. Old: the frame guard on the second element of a crash tuple. New: the guard `is_stacktrace/1` on any list in the walk, with the same frame test (two atoms, an integer arity or an argument list, a list location) on the first element.
3. Old: `Exception.normalize/3` got the real stack, so `:undef` and `:function_clause` named the function from the top frame. New: it gets `[]`, so these name no function. The stream path is not changed: `Helyx.Provider.Loop` normalizes an `:error` with its stack before Core sees it.
4. Old: the fallback when a plugin `message/1` fails is the exception name. Kept.
5. Old: `inspect` with `safe: false` in a catch. Kept, now on the cleaned term for the text, and on the raw term for the log.
6. New bound: the walk visits at most 10,000 terms (`@max_nodes`); the rest of each open term becomes `:cut`. A struct keeps its `__struct__` and `__exception__` pairs at no cost, so a cut exception still writes its message. The known ceiling of `inspect` on a huge map or tuple now holds only for the log line.
7. Tests of the old mechanism: every crash shape test of `stream_events_test.exs` and `provider_process_test.exs` passes unchanged, so each shape keeps its short message. The fallback tests keep the name. The test of a provider error list that looks like a stacktrace keeps its term.
8. What clients see that changes: a stacktrace inside a reason that is not a crash shape (an exception field, a `MatchError` term, a supervisor failure, a map key) shows as `:stacktrace`; a reason over 10,000 terms shows `:cut` past the bound; a provider error `{reason, :stacktrace}` reads as a crash.
9. State with no bound: none new. The walk is bounded, and the log line keeps its bound.
