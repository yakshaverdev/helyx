# Review: the challenge and the proof (#763)

Scope: `Helyx.Transport.WebSocket` (`child_spec/1`, `start_link/1`, the key closure, protocol 2), `Helyx.Transport.WebSocket.Connection` (`challenge` at `init/1`, `proof?/3`, the order of the protocol and proof checks), the conformance client `Helyx.Test.WireClient`, the transport tests; `docs/features/wire-protocol.md`, ADR 0008 (revision of 2026-10-18).

Invariant: no WebSocket frame, plug option, process state of the transport, child spec from `child_spec/1`, or log of the WebSocket server (the `:tcp_error` crash report with the fragment buffer, the handshake exception with `conn` in its metadata, the TLS-sniff warning with the plug options) holds the token or its key, the SHA-256 of the token. The server sends one `challenge` with a nonce of 32 random bytes per connection; `hello` carries `proof`, the base64 of HMAC-SHA256 of the nonce with the key, compared in constant time; protocol 2 checks the protocol number before the proof; the auth wait stays 5,000 ms from the upgrade.

Accepted holes: a product that writes its own child spec, or calls `start_link/1` with a binary token, keeps that term as written; an old client that still sends a token in `hello` puts it in the frame buffer; `refused` gives the server protocol number to a peer that gave no proof.
