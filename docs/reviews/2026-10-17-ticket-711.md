## Proofs before the deletion

1. **Hands (S4), deleted.** `grep -rn unconfirmed` over `lib`, `plugins`, `test`, and `docs`: the field `unconfirmed` of `Helyx.Session.Hands.State` had two writes, `Release.add(state.unconfirmed, left)` at `hands.ex:221` and `:303`, and two reads, `state.unconfirmed == %{}` at `:229` and `:238`. Two tests set it with `:sys.replace_state/2` (`hands_busy_test.exs:77`, `summary_test.exs:198`). Nothing read the handles. They go to the log in `Release.error/1` (`release.ex:48`), which both writes call with the same `left`. The map is now the boolean `unconfirmed?`, set when `left != %{}`. `Release.add/2` stays: the cancel builds its handles per tool with it (`hands.ex:215`).
2. **Bash (S7), deleted.** `grep -rn run_command`: the callers of `Helyx.Tool.Bash.run_command/3` were `bash.ex:125` and four tests (`bash_test.exs:285, 294, 310, 335`), each with `@load_start_ms 3_000`. `run(%{"command" => c, "timeout" => 3}, dir)` reaches `run_command(c, dir, 3_000)`: the commands have no NUL, and `workdir` and `background` are missing. `run_command/3` is now private, and the four tests call `run/2` through `run_limited/2`. `bash_test.exs`, "the timeout argument stops the command through the hands", already ran the limit through `run/2`.
3. **Claude Code (S6), kept.** The proof says that every write of `turn: nil` comes after an `init` line. `turn_result/2` (`claude_code.ex:493-495`) writes `turn: nil` after `started` of the turn's line and does not need `init?`. A temporary probe through `Helyx.Test.ClaudeCodeFake` reached the state: a provider with `resume_id: stored(sid())`, a turn, and program output `started`, `result("x")`, `lost(sid())`, with no `init`. The result ends the turn (`turn: nil`, `init?: false`), the lost result sets `terminal: :lost`, and `read/2` calls `relaunch/2` with no turn. The settled state was `{turn: nil, init?: false, terminal: nil}` with `resume: nil` (only `Program.replace/2` clears it). Without the `%State{turn: nil}` branch, `write_turn/1` gets a nil turn and the provider crashes. The spec agent ran the probe again with the same result. The real program sends `init` before the result of a query, but its output is a boundary, so the branch stays.
