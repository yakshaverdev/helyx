# Review: ticket #658, the tail snapshot and the history pages

Scope: `Helyx.Session.subscribe/2` (the `tail` option), `Helyx.Session.history/4`
(new), `Helyx.Session.History` (new: the option check and the cut),
`Helyx.Session.Totals` (new: the fold that `Helyx.TUI.SessionUsage` had),
`Helyx.Session.Call` (the call helpers, moved from `session.ex`),
`Helyx.Session.Snapshot` (fields `more`, `usage`, `context`),
`Helyx.Session.Server.Calls` and `Events`, `Helyx.TUI.ViewModel` and
`Helyx.TUI.Footer`, and the docs `session-snapshot.md`, `usage-and-limits.md`,
`wire-protocol.md`, `session-subscribers.md`.

Invariant: `subscribe(session, tail: n)` returns at most `n` (1 to 1,000) of
the newest messages and 16 MiB by `:erlang.external_size/1`, cut so that the
first one is a user or an assistant message, else the newest group alone,
with `usage` and `context` folded over every message of the transcript; and
`history/4` returns the page before a message id of the live transcript with
the same cut and an explicit `next` cursor, and changes no session state.

State at the commit: one round. It reproduced no code defect, so the loop
ended (`/ship`, "A round that reproduces no defect ends the loop").

## Round 1

Simplify (4 agents) before the round: the two option checks became one
`count/3`; the unused type `page` went; a page reads the messages before
`before` in one pass, newest first, instead of a split and a reverse; the doc
of history in the feature doc names `next`. Skipped: a cut with no full
reverse of the transcript (the totals fold is O(n) at each subscribe anyway,
about 8 ms at 50,000 messages, measured by the agent); a cut by whole groups
(it gives the same result); the context state inside `Totals` (the wire has
`usage` and `context` as two fields); the context estimate of
`Helyx.Compaction.Summary` (`summary.ex:188-216`), which differs from
`Totals.context/2` in two rules and is out of scope.

Resolutions:

1. Spec: a `before` that is the id of a tool result ends the page inside
   its group (probe of `History.page/3` on `u1 a1(c1,c2) r1 r2 u2` with
   `r2`). The page is still the messages before `before`, as the wire doc
   states, and no result is in a page without its call; the call shows as
   open, and the rest of the group is in the messages the client holds. The
   cursors that Core gives always name a user or an assistant message. Doc:
   `session-snapshot.md`, "History", states it. No code change.
2. Standards: no "Replaced mechanism" section. Added to `session-snapshot.md`.
3. Standards, spec, failure path: stale names. `session-subscribers.md` S1
   and the ownership row name `{:subscribe, pid, tail}`; `session-snapshot.md`
   step 1 and the call row name `subscribe/2` and `history/4`;
   `wire-protocol.md` has the new line numbers of `session.ex` and no stale
   line numbers of `events.ex`. Mentions of `subscribe/1` elsewhere stay:
   the default argument defines `subscribe/1`, the full snapshot.
4. Spec, failure path: no bounds row for the wait of the page call. The row
   "snapshot call and page call" covers both.
5. Spec: no test of a tail during a turn. Added
   (`tail_snapshot_test.exs`, "a tail during a turn keeps the turn and its
   partial").
6. Failure path: `or dropped != []` in the `more` of the cut cannot decide
   the result, because a dropped result has its call in the older
   messages. Removed, with a comment at the line.
7. Standards: `Helyx.Session.Call` split for the line count. Kept: the
   module owns the call decision (the deadline, the timeout exit, the
   not-found answer) of every call, the page call too. The worker brief also
   asked to keep `session.ex` under 400 lines with #657 in parallel. The
   one-line `defp call/3` stays, so the calls of #657 merge without an edit.
8. Standards, judgement: the reason in the `@doc` of `Totals.add/2` is now
   a short contract sentence; the long doc line of `ViewModel.from_snapshot/1`
   is wrapped.
9. Not changed, judgement: bare maps for `context` and the page (the
   snapshot `turn` and `queue` are maps too, and the wire shapes are maps);
   the field name `context` (the wire schema names it); the guard on the ids
   of `history/4` (a type error of an Elixir caller, as the `is_binary` guards
   of `prompt/3`); a shared test builder of `%Snapshot{}`.
10. Spec, doubtful: the ticket says that the limit counts messages, not
    bytes; ADR 0008 §4 and §5 state 16 MiB of message content too. The code
    follows the ADR, which holds the contract. The ticket default of 200 is
    the default of `history/4` and the transport's for a tail; Core has no
    tail default, because `subscribe/1` is the full snapshot until #662.
    `:invalid_limit` is the Core error that the transport maps to
    `bad_params` (#660).

The fixes of 6 and 5 are one line of code and one test; the round reproduced
no defect, so no further round runs for them.
