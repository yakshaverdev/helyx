# Review: #494 No tool call runs from a reply cut at the token limit

Invariant: when a model reply that `Helyx.Provider.Loop` consumes ends with a `done` whose stop reason is `:max_tokens` and the reply holds at least one tool call, Loop (`terminal/2`) sends `message_end` and no `tool_request`. Every call of the reply gets the error result "tool call not run: the reply was cut at the token limit" (`Helyx.Session.Stream.not_run/1`) as a `tool_result` event, in call order, through `send_ready/2`. Then the held steers and `need_context` go out, and the model is called again in the same turn. Other stop reasons, and a `:max_tokens` done with no calls, are unchanged.

Out of scope (ticket): the harness providers Claude Code and Codex run their own tool loops, so Helyx never holds their calls.

Accepted: a model that cuts every reply gets one more model call for each cut, with no limit. This is not new: before the change the calls ran and the model was called again in the same way. The user aborts the turn.
