# Review: a second start names an address only after the handshake (#777, item 1)

Scope: the working tree against the branch base `63de2e01`. Files: `apps/coding_agent/lib/coding_agent/serve.ex`, `apps/coding_agent/test/coding_agent/serve_test.exs`, `docs/features/serve.md`, `docs/features/tui-attach.md`.

Invariant: a second `helyx serve` that finds the lock of its data folder held names an address only after `Helyx.TUI.Wire.connect/4` passed the handshake with the token of `server.json` up to `welcome`; every other result is a server in its start, tried again every 100 ms with no attempt after 5,000 ms, each connect within 5,000 ms.

## Decision

- Only item 1 is in scope (the triage comment of the orchestrator, 2026-10-20). Items 3 and 4 were closed by #661. Item 2, the FIFO, keeps its text "open, ticket #777": the triage calls it an accepted hole, but `docs/agents/review-checklist.md` ("Races and resource ownership") says that a race is never accepted by who the caller is, so this change does not write that text. The orchestrator decides it.
- The second start calls `Helyx.TUI.Wire.connect/4`, the handshake of `CodingAgent.Attach.connect/1`, not `Attach.connect/1` itself: `Attach` calls `Serve` (`read_file/1`, `wait_ms/0`, `url/2`), it tests the lock again at each attempt, and it returns no address.
- `welcome` is the only proof. The transport sends `refused` before it checks the proof (`plugins/bundled/lib/helyx/transport/web_socket/connection.ex:77-85`), so a `refused` proves no token and is a server in its start for a second start. A client keeps its own rule (`tui-attach.md`, decisions 5 and 6).

## Simplify

One agent. Kept: the comment of `@connect_ms` says "one attempt", as `Attach` does; "means that the server is starting", the wording of the docs; `fake/1` takes its caller; the `WebSocket` alias in the test. No behaviour change. After it, `mix format` split an `if ..., else:` over two lines; it is a block now.

## Open at the commit

The code of `serve.ex` had no reproduced defect in rounds 2 and 3. Rounds 1 to 3 reviewed the committed tree. The limit of 45 minutes of work ended the loop after round 3, so these gaps of the tests stay open:

- The mute phase of the slow test "a second start tries again every 100 ms, each connect within its bound" passes with a connect bound up to about 10,900 ms. The fix: a trace of the fourth argument of `Helyx.TUI.Wire.connect/4` with `calls/2` (it must be 5,000), or the bound `5_000 + 100 + @load_ms` for a phase whose one attempt starts at once.
- The count test proves a gap of at least 100 ms between attempts, not of at most 100 ms: a poll of 500 ms or 2,000 ms passes. A load-safe upper bound of the gap needs a margin that a slower poll also passes.
