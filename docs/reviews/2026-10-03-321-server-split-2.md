## Invariant

The split of `server.ex` into `Server.Steering` (the only writer of `queues`, and the steer effects), `Server.Stop` (the stop order and its bounds, a session shutdown of 30,000 ms), and the provider connection functions in `Server.State` (`connect/1`, `arm_idle/1`, `close_switched/1`, `await_ended_provider/1`, `base_opts/1`) is a pure move. It changes no behaviour of any GenServer callback of the session or of its child spec, the #339 drop of a program turn through `State.drop_turn/2` and the wait's provider pid included, and every comment that stays is true against the code.

Codex was unavailable (usage limit until 2026-10-04). A fresh general-purpose agent ran the same adversarial review with the same invariant sentence and base, and counts as the Codex reviewer.

## Placement decisions

- The ticket says "next to `ProviderConn`". The connection functions are in the `State` module, in `state.ex`, where `ProviderConn` is defined. A function in the `ProviderConn` module cannot match `%State{}`: `State` is compiled after it and matches `%ProviderConn{}` itself.
- `queue_reply` became `Steering.queue/3` with the return the ticket names. A three-line `queue_reply/3` in `Server` makes the GenServer reply.
- `start_queued/1` drains through the new `Steering.drain/1`, so no code in `Server` writes `queues`.
- `Stop.run/1` is the one entry for `terminate/2`; `end_work/1` and `stop_hands/1` are private.
- The close clause of `close_or_start/2` is `State.close_switched/1`. `settle/1` is a `with` chain. When the chain stops at a wait, the old code called `arm_idle/1` on that wait, which did nothing.
