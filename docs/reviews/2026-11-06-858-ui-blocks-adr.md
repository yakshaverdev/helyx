## Round 1 (first round): Codex and spec

- Codex: one finding, medium. `kind` had no bound, so the cut replacement `{kind, text, cut: true}` could not fit 65,536 bytes (a kind of 65,536 bytes gives 65,568 bytes of JSON). Fixed: `kind` is 1 to 64 bytes of `a`-`z`, `0`-`9`, `_`, which need no escape.
- Spec: the same kind bound; `cut_result/1` budgets raw bytes, not JSON (fixed: the build adds a cut with a JSON budget); no rule for a bad block on disk (fixed: drop the block, keep the message); no rate bound on `:ui_block` (recorded, then corrected in round 2); `key` unbounded (fixed: 1 to 64 bytes); provider results unclear (fixed: blocks only on Helyx tool results); a bounds row cited the wrong bounds (fixed); an emitter can set `cut` (fixed: `cut: true` means cut, by Core or the emitter). ADR number: `0010-hub.md` is on the #857 branch; this ticket uses 0011 as the orchestrator set.
- Guarantee table of existing behaviour (spec agent): `Run.tool/3` outside-contract result (`lib/helyx/session/hands/run.ex:12-21`); `max_result_bytes/0` 65,536 (`lib/helyx/data/message.ex:186`); `cut_result/1` (`message.ex:252-283`); `ask/1` 65,536 and raise (`lib/helyx/interfaces/tool.ex:249-271`); `check_answer/1` 16,384 (`lib/helyx/session.ex:233,256`); TUI picks the picker by tool name (`question.ex:62`); `:notice` not in the transcript (`lib/helyx/interfaces/event.ex:83-86`); snapshot `asks` (`lib/helyx/data/session/snapshot.ex`); credits, ring, protocol number (ADR 0008 §4, §5, §7). Everything else is a decision for later tickets.

## Round 2 (reduced): spec and failure path

Invariant: every UI block that a client or the file gets is within its bound, and every input has a defined failure path at its boundary.

Findings, all fixed in the ADR:

- An ask request that is a UI block got no envelope check. Fixed: a request with `kind` gets the checks of `kind`, `text`, `cut`.
- The snapshot (newest block per key) disagreed with the live drop at a call's result and let two calls' keys collide. Fixed: the snapshot is the fold, keyed by call id and key, for calls with no result yet.
- No failure path for a `ui_blocks` over the count or not a list on disk, and the over-cap failures were left to the feature doc. Fixed: live over the count is outside the contract; at read the blocks past it, or the whole bad field, are dropped; a new key past the key count is a contract break of the emitter.
- `Input.json_object/2` returns one `:error` for "over the bound" and "not JSON", so it cannot drive a cut. Fixed: the check walks the whole block and counts.
- The credits count events, not bytes (`lib/helyx/session/server/events.ex:15-16`). Fixed the bounds row: a `:ui_block` is bounded as every event is (ADR 0008 §5), and the emit is a call that waits for the session.
- A provider block for an unknown call and one from a background run were undefined. Fixed in round 2 as malformed; corrected in round 3.

## Round 3 (reduced): spec and failure path

Invariant: as round 2, and the snapshot equals the fold of the events.

Findings:

- The ADR said #673 bounds a message at read at 8 MiB. False: the read checks only 1,024 content blocks (`lib/helyx/session/file/codec.ex:65-72`); the byte bound was reverted in #687. Fixed, and the file growth is an accepted hole stated in the ADR.
- A `form` whose `text` copies the questions would push the largest question request over 65,536 bytes. Measured: the largest request today is 59,587 bytes of JSON. Fixed: the `text` of a `form` is a short line.
- A provider check for "a running call" cannot be in `Stream.check/1`, which runs in the provider process with no turn state, and `ToolQueue.running` holds only Helyx calls; a block can also be in flight when its call ends. Fixed: a provider names only an open call that it runs itself, the session checks it, and a block for another call is dropped, as a provider result for no open call is (`lib/helyx/session/server/records.ex:55`).
- The ask already proves JSON, UTF-8, and size with `json_object/2`; the ADR no longer asks to repeat that walk there.
- Wording: the walk counts escapes without an escaped copy; the reader bounds the file, not a line; a provider and a tool never share the keys of one call.

The round-3 fixes are text in one doc file. The loop is at its limit (three rounds, 45 minutes), so they got no further review round. They are reported to the caller as unreviewed.

## Accepted holes

- No rate cap on `:ui_block` in Core: a tight loop fills the replay ring, and a reconnect gets a tail snapshot, which holds the newest block of each call id and key.
- UI blocks make a session file grow faster; a file past 64 MiB or the heap cap of its parse fails to resume, as any session does.
- A client that does not know an input kind gives no answer; the ask waits for another client or the abort.
