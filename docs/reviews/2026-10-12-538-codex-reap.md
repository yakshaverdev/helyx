# Review: #538 Stop the Codex review broker of a removed worktree

Invariant: `.claude/skills/ship/codex-reap.sh` sends SIGTERM only to a `node` process of the current user whose command line has the broker shape (`app-server-broker.mjs serve`, endpoint `unix:<S>/broker.sock`, the cwd, then pid file `<S>/broker.pid` as the last argument), and only when the cwd, cut between the two anchors that both name `<S>`, is gone: `stat` on it fails with ENOENT. A broker whose cwd path still names a directory never gets the signal. A directory moved away from its path counts as gone (3.2). The entry points are the script with an optional absolute scope directory (the test uses it to touch only its own fakes), and `/orchestrate` step 5.6 and the end of the run.

Accepted holes: a cwd that `ps` prints with a code (`\`, `^` or `M-`, which in the C locale is every byte outside printable ASCII), a relative cwd, a cwd with a `..` component, and a cwd whose lookup fails with any error but ENOENT are skipped, so such a broker is never signalled. The `M-` mark also skips a plain name that holds `M-`, such as `PM-12`; the script then does not send the signal. A parked worktree keeps its broker, by design. The script does not wait for the broker to exit. Not verified: that `codex app-server` ends its own children when the broker closes it; the brief allows only fake brokers, so the user story "no Codex process from a removed worktree is left" is proved only to the broker's SIGTERM handler. Open, ticket #541 (comment): a directory made again at the cwd between `stat` and `kill`. Open, ticket #541: the pid can be reused between the one `ps` read and the `kill`. Out of scope: a change to the Codex plugin.

The test is `.claude/skills/ship/codex-reap-test.sh`. It runs by hand; `mix precommit` does not run it.
