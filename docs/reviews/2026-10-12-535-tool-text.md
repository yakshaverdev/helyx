# Review: tool results and CLI errors with no stacktrace or raw plugin term (#535)

Scope: the new public module `Helyx.Reason` (the cleaning walk of #509, moved out of `Helyx.Session.Server.Events`), its callers in `Helyx.Session.Server.Wait`, `Helyx.Session.Hands`, `CodingAgent`, and `CodingAgent.CLI`, the `:context_timeout` reason of a prepare Task in `TurnLoop`, the dead `end_turn(:stream_ended, _)` clause, the docs (`session-lifecycle.md` step 5 and the bounds table, `coding-agent.md`), and a new line in `docs/agents/review-checklist.md`.

The invariant of every review brief: a term that Helyx does not control (the crash reason of a tool Task, a value that a tool raises, throws, or exits with, a tool return outside the contract, an unreleased plugin handle, the reason of a failed turn, a start error of the coding agent with no clause of its own) reaches a tool result, a client event, the session file, or the stderr line only as `Helyx.Reason.text/1` (no stacktrace, at most 4000 bytes, valid UTF-8) or as a fixed text, and the log gets the term with a bound.

## Decisions

- Owner of the text: `Helyx.Reason`, in `lib/helyx/data/`, with `text/1` and `log/2`. It is public, so `Hands` and the app call it without a session-server internal. `text/1` does not log, because the app must not write a log line on the terminal.
- A raise in a tool gives the message of its exception (`{reason, stacktrace}` is a crash for the walk). A throw or an exit gives `{kind, value}`, cleaned. A return outside the contract and an unreleased handle give a fixed text; the log has the term.
- A pid inside a thrown or exited value shows as characters. The ticket design, step 3, says that a raise, throw, or exit gives "the text of the cleaned reason", and #509 accepted the same for the turn error. The user story says "never pids"; the two disagree, and this change follows the design. Open for the coordinator.
- A4: `CodingAgent.error_text/1` makes the whole line after `helyx: `. `{:session_down, reason}`, the exit of `Helyx.TUI.run/1` when its session ends (`tui.ex:148`, `:187`), gives `the session stopped` or `the session crashed and stopped`; every other error gets `could not start the agent: `. A crash of the TUI itself during the run still reads as a failed start: `Helyx.TUI.run/1` returns both its init failure and a later crash as `{:error, reason}`, and the ticket points at the session end only. Accepted.
- The integer clause of `clean/2` stays. The ticket item: delete it only if a boundary proves the digit cap for every caller. No boundary caps the value that a tool raises, throws, or exits with (`Hands.run_tool/3` catch, and the `:DOWN` of a tool Task, which `down_reason/1` does not see), nor a start error of the app. Probe `scratchpad/int535.exs`: `Helyx.Reason.text({:throw, n})` with a 400,000-digit `n` takes 3 ms; `inspect` of the same term takes 4,097 ms. Test: "a tool that throws a huge integer gives the digit marker" (`hands_test.exs`).
- `:context_timeout` names the prepare Task killed at its bound, next to `:provider_timeout`, after the glossary term "Context". As for `:provider_timeout`, any `:killed` exit reads as the timeout.

## Gate r1 (Codex): 1 finding, confirmed

`Helyx.Reason.message/1` called the `message/1` of the exception. The message of `MatchError` runs a safe `inspect` of its term, and a plugin `Inspect` that raises there gives `#Inspect.Error<...>` text with the stack of that raise. That text is a string, so the catch did not run, and the stack reached the tool result and the CLI line. Reproduced through a tool for `MatchError`, `CaseClauseError`, `KeyError`, `BadMapError`, `WithClauseError`, `TryClauseError`, `BadStructError`, `BadBooleanError`, `Protocol.UndefinedError`, and the Erlang forms `{:badmatch, _}`, `{:case_clause, _}`, `{:badkey, _, _}`. #509 had stated this case as a ceiling with no handler (step 5 and the checklist); the coordinator asked for the fix, and both texts now state the rule.

Escape class: the #509 class (a stacktrace in the error text), now in the message step. Second time for this class, so the mechanical check is a test through the tool boundary, and the checklist line names the rule.

The invariant of the fix (coordinator): no stacktrace reaches the text through any exception message that Helyx makes, whatever the exception.
