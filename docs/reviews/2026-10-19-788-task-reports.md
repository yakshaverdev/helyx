# Review: the crashes of session Tasks and the provider process hold no message text (#788)

Scope: the working tree against `39bc678b`, the merge base of the branch. Feature doc: `docs/features/session-lifecycle.md`, "Log and crash reports".

Invariant: a raise, a throw, or an exit with a term in the body of a process that Core starts for plugin code in a session (the prepare Task, a recall call, a sync call, a release Task, the provider process) runs in `Helyx.Reason.task/2`. It logs `<label>: <kind>` as an error and no message text, and it ends the process by an exit signal to itself with the exit reason of a Task crash (frame arguments replaced by their count). So `Task` writes no crash report, and each link and monitor gets a reason of the same shape as before. An exit with an atom or `{:shutdown, term}` continues with no change. A tool Task (`Hands.Run`) and the model Task of `Helyx.Provider.Loop` already catch every crash. Accepted holes: the SASL reports, the raw exit reason that links and monitors get, and processes that a plugin starts itself.

## Reproduction

`test/helyx/session/log_test.exs` on the code before the fix: 5 of the 6 new tests failed. The `Task` report of the prepare, recall, sync, release, and provider Tasks printed `** (KeyError) key "the text of a plugin crash" not found`, and the frame `:erlang.map_get("the text of a plugin crash", %{})`. The release report also printed `Args: [[:handle], :deliver, <deadline>]`. The tool test passed before the fix: `Hands.Run` catches every crash of a tool.

## Decisions (owner away)

- The mechanism: `Task` writes its report with the same term as its exit reason, so a report with the kind only and a raw exit reason need a body that never raises. `task/2` catches, logs the kind, and ends the process with `Process.exit(self(), reason)`. The alternatives changed the reason that the consumers get: `exit({:shutdown, reason})` needs an unwrap in the prepare, recall, sync, and provider consumers; a crash as a result value needs a new clause in each consumer and is ambiguous with a plugin return. The signal keeps every consumer as it is, which is the smallest change in Core. Probe of 2026-10-19 (scratch script): the `:DOWN` and the `:EXIT` reason of a Task that ends this way equal the reason, also with a trap set first, and the log is empty.
- An exit with an atom passes through: a signal with `:kill` gives `:killed`, which the prepare and provider consumers read as a timeout. An atom is its own kind (#756), so the `Task` report holds no text. `{:shutdown, term}` passes through: `Task` does not report it, and `Helyx.Provider.Loop` stops the provider process with it.
- The tool Task gets no wrapper: `Hands.Run` catches every class, so a crash in the Task body is a bug of Core only.
- The release Task moved from the MFA form to a closure, so a report no longer prints the handles, the mode, and the deadline as `Args`.

## Simplify

One agent. Applied: `task/2` runs `fun` in `no_args/1`, which removes two maps of the stack, and `Process.sleep(:infinity)` replaces a bare `receive`. Skipped: a guard macro, a wrapper of the five call sites (it would make `Helyx.Reason` know supervisors), and a merge of the two hands builders in `log_test.exs`.

Resolution:

- Fixed (false sentence): "`Task` reports an atom" was false for `:normal` and `:shutdown`. The doc and the `@doc` of `task/2` now say that `Task` reports no `:normal`, `:shutdown`, or `{:shutdown, term}`. "The provider process writes no report at any other end" was false for an atom exit of a callback: the doc now says that the loop ends with `{:shutdown, reason}`, which `Task` does not report.
- Fixed (test gaps): `reason_test.exs` now checks that the Task writes one log line and no `Task` report, that an atom exit gets the `Task` report, and that a shutdown gets no line. `provider_process_test.exs`, "a crash in a callback fails the turn with text", now refutes the message on the real provider path and checks `provider process crashed: RuntimeError`.
- Fixed (qualifiers and wording): the moduledoc of `Helyx.Reason` and the lead of the doc section now name the holes; long sentences are split; "every one of its model call" now has its verb; the trap is cleared before the signal, not at the start; the replaced mechanism says that no test read the old report. The comment of `Process.sleep(:infinity)` says why it waits: the docs of `erlang:exit/2` do not say that the process ends before the call returns. The failure-path agent called the line dead code; it is the wait for that signal, not a fallback.
- Rejected: a wrapper that starts the Task (Shotgun Surgery): the explicit shape matches the `no_args/1` sites of #756, and a wrapper would make `Helyx.Reason` know supervisors. The name `task/2`: it runs the body of a Task, as `no_args/1` runs a callback. `exit_reason/3` against `Helyx.Provider.Loop.run/5`: the loop normalizes an error, `Task` does not. A private function for the prepare body: it would take eight arguments. Refuting other forms of the secret: the secret is ASCII, so its `inspect` and charlist forms hold it. ADR 0006: the ticket names the feature doc only.
- Not proven (stated hole, from #756): the proc_lib crash report and the message queue with SASL on. The spec probe saw the supervisor report hold the message of the exception, and no proc_lib report for a Task.
