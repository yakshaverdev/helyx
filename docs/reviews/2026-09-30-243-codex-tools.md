# Review: Helyx tools inside Codex (#243)

Date: 2026-09-30. Base: `e21db41` (an early #241 commit), then a rebase on `origin/master`. Invariant: the Codex provider offers the session's Helyx tools as `dynamicTools` at `thread/start` only when `initialize` accepts `experimentalApi`; each `item/tool/call` of an open `dynamicToolCall` item of the running turn gives one `{:tool_request, ...}` and gets exactly one written answer, whatever its JSON-RPC id; every other call gets an error answer and no request; every stored harness session id passes `Helyx.Message.harness_id?/1` and resumes only a thread with the same tool set; when the tools are off, the first turn gives a notice. Entry points: the `harness_init/3` handshake, the `harness_info/2` lines, and the `{:tool_result, ...}` request. Accepted holes (feature doc, "Built in #243"): the transcript names a call `dynamicToolCall`; the digest order can change for maps with more than 32 keys; a thread id with `#` starts a new thread; a tool name outside `^[a-zA-Z0-9_-]+$` is not checked.

## Simplify

- Applied: `tool_answer/4` returns the state (the `tool_error` wrapper is removed); `hex_digest/2` is shared by the digest and `call_id/1`.
- Skipped: efficiency findings on work that runs once for each connect; nesting and order judgement calls; a helper shared with the Claude Code provider (ADR 0005: one plugin never calls another).
