# Review: #608 a crash right after the TUI start shows noproc

Invariant: `Helyx.TUI.run/1` returns the real exit reason of a TUI that died, never `{:error, :noproc}`, and `:ok` for `:normal`. After `Process.monitor/1` it asks `Process.info(pid, :status)`. The TUI answers that only after it handles the monitor signal (the OTP 28 docs of `process_info/2`: "Getting process information follows the signal ordering guarantees"), so a live answer means the DOWN carries the real reason. With no answer the TUI died before the monitor: the caller, still linked and trapping exits, waits for the `EXIT`, flushes the `:noproc` DOWN, and restores the flag.

Files: `plugins/bundled/lib/helyx/tui.ex`, `plugins/bundled/test/helyx/tui_test.exs`.

Base: `origin/master` for both rounds; round 2 had no commit before the fix. `origin/master` moved during the work with an unrelated change to `.claude/skills/orchestrate/SKILL.md`; the reviewers used `git diff HEAD` for round 2.

Bounds sensor, round 1: `bounds sensor: 2 candidate functions, 0 flagged, 0 without an answer`. Round 2: `bounds sensor: 1 candidate functions, 0 flagged, 0 without an answer`.
