# Review: word wrap, margins, marked user messages, compact notices, lighter input box (#483)

Date: 2026-10-04. Base: `origin/master` 58ae388.

Invariant: the TUI transcript, composer, and status bar draw inside a margin of 2 columns on each side, and the scroll screen takes the width that `Layout.split/4` draws from `inner_width/1` of `Helyx.TUI`; `Helyx.TUI.Wrap.rows/2` breaks a line at a space, and inside a word only when the word (with the indent before it on the first row) is wider than the row, drops the space at a break, and keeps every row within the width but a glyph wider than the whole width; a user row has a bar and a tint, with a fill of spaces that runs past the edge, and no bar when its glyph is wider than the text width; a run of information cells is one transcript item and one dim row, so a scroll position indexes items. Accepted holes: a run of information cells is unbounded in length, like a message; continuation rows of tool output lose their indent; a scrolled view has no empty row above the composer; the tint is palette white on black.

Checked before the build: ExRatatui 0.14.1 has `Block.border_type: :rounded`, `Block.padding`, `Block.border_style`, `Style` palette colors (`:black`, `:white`, `:blue`, `:dark_gray`), `Layout.split/4` with `horizontal_margin`, and clips every widget area to the buffer (`render_widget_data/4` in `rendering.rs`). `Textarea` has no prefix field, so the `›` mark is a second widget. Its `Paragraph` does not fill a line style past the last grapheme, so a user row carries its own fill.

## Simplify

- Reuse and altitude: `inset/1` copied the `horizontal_margin` option of `Layout.split/4`. Fixed: the render uses the option; `inner_width/1` stays for the scroll screen and gives 0 below 4 columns, where ratatui draws nothing.
- Simplification: `break/4` had three branches for two results. Fixed.
- Simplification and altitude: the padding of the box and the column of the mark were two numbers that must agree. Fixed: both come from `@text_column`.
- Altitude: the scroll comments still said "cell" for the position unit. Fixed: "item".
- Altitude: join the information cells in `ViewModel.add_cell/2` instead of the transcript. Skipped: the join is a matter of the look, the view model stays one cell per event, and the item rule needs no change to the snapshot fold.
- Altitude: a prefix argument for `styled_lines/3`, so tool output keeps its indent on every row. Skipped: outside the ticket; an accepted hole above.
- Efficiency: `Wrap.columns/1` measures a user row a second time; an information run wraps whole when it shows. Skipped: small, and the second is stated in the bounds table.
