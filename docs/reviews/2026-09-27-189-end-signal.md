# Review: the end signal (#189)

Feature doc: `docs/features/end-signal.md`. Ticket: #189.

## Round 1 (full)

Bounds sensor: `bounds sensor skipped: TYPESAFE_API_KEY is not set`.

Simplify (before the review): one flush `receive` for the two signals; `call_pid/3` default timeout; a `subscribe!/1` helper in the TUI for the two subscribe sites; the test helper `mailbox/0` moved to the top of `session_test.exs`. Skipped: the altitude proposal of one watch per session with `Registry.dispatch` of the end signal. It leaves a trapping subscriber with only the `{:EXIT, partition, _}` of the link, which is not contract data, so the lost signal needs a process per subscription in any case.

### Failure path

| Finding | Resolution |

Test: "a second subscribe replaces the watch" |

Test runs: two timing flakes in untouched tests under load (`the session supervisor after a resume (#103)` timed out once; `Helyx.Session.HandsTest` "a release just past the deadline" failed once). Each passed on three reruns.

## Round 2 (full)

Simplify: 7 findings. Applied: a shorter partition note in the watch, a shorter exit comment, an `if` in place of a `with`, a narrower rescue in the register. Skipped: `:sys.get_state/1` as the barrier (a `:sys` call is answered while the supervisor is suspended, ahead of the exit, so it breaks the barrier); a `queued?` test helper (two uses); one `leave` on `:ignore` (it is the same path).

### Standards

0 hard findings, 5 judgement calls. Applied: explicit `else` clauses in `subscribe/1`; `ready/1` renamed to `await_supervisor/1`. Kept: the other three (naming and comment length).

### Spec

| Finding | Resolution |
| --- | --- |
| A late lost signal of an old watch can reach a newer subscription | Fixed with the failure path finding below |
| The rescue path of `subscribe/1` kept the old watch | Fixed: every exit path of `subscribe/1` calls `leave/2` |
| The watch has no catch-all `handle_info/2` | Kept: only the two monitors and the partition link send to it, and the barrier calls use an alias. Any other message is a bug, so it crashes (AGENTS.md). A comment in the watch states this |
| Doc: "a crash of the Registry supervisor" in Tests; "stated in `Helyx.Core`" | Fixed: "a kill of the Registry supervisor while the Core is suspended"; "set explicitly in `Helyx.Core`" |

### Failure path

| Finding | Resolution |
| --- | --- |
| Confirms the round 1 fix. New: `leave/2` found the old watch through `Registry.values/3`. After a restart, the new Registry does not have the old entry, so a subscribe in the window before the lost signal did not stop the old watch, and its lost signal reached the new, healthy subscription | Second finding on the same mechanism, so the mechanism changed: the caller keeps its watch in its process dictionary under `{Helyx.Session.Watch, core, id}`. `leave/2` stops and flushes that watch, whether or not the Registry still has the entry. Only the caller subscribes itself, so no other process changes the entry. Test: "a subscribe after a restart stops the old watch that has not signalled" (the BIF suspend holds the old watch inside its barrier call). Bounds table: one dictionary entry for each `{core, id}` |

The fix is under 100 code lines.

## Round 3 (full)

Simplify: 2 findings. Applied (efficiency): `leave/2` kills the old watch and waits for its `:DOWN` instead of `GenServer.stop/1`. The stop waited while the old watch waited in its barrier, up to 10 seconds, and blocked a TUI that subscribes again after a Registry restart. The signals of one process arrive in order, so the flush still removes a signal of the watch. The test holds the old watch with the BIF suspend, and the kill ends it. Skipped: `if watch = Process.delete(...)` (an assignment in a condition; the `case` is as short).

### Standards

1 hard finding, 4 judgement calls.

| Finding | Resolution |
| --- | --- |
| Hard: the dictionary entries had no bound; an entry stayed after its signal | Fixed: each subscribe removes the entries of dead watches, so the entries are the live watches of the caller plus those that died since its last subscribe. The flush for the id runs in `leave/2` whether or not an entry exists, so a removed entry does not leave an old signal after a new subscribe. Test: "a subscribe removes the entries of dead watches and keeps their signals" |
| `leave/2` returned an error tuple on success | Fixed: `leave/2` returns `:ok`; `not_found/2` returns the error |
| The flush matches the id only, not the Core | Documented as a hole under #204 |
| The Tests section did not list two tests | Fixed |
| The new test can leave a BIF-suspended watch when an early assertion fails | Kept: the watch monitors the test process and ends with it |

### Spec

| Finding | Resolution |
| --- | --- |
| A timeout of the first barrier call still called the Core (up to 10 s), but the doc says a timeout sends the lost signal at once | Fixed: `await_supervisor/1` treats `{:timeout, _}` as `:ok` |
| Step 1 of Subscribe did not say it stops the old watch; the life of a watch did not name a later subscribe | Fixed in the doc |
| The flush can remove the signal of another Core | Same as the standards item: #204 |

### Failure path

No finding breaks the invariant. The reviewer checked every exit path of `subscribe/1`, a Registry restart at each step, the kill inside the barrier, and the flush order.

| Finding | Resolution |
| --- | --- |
| Reproduced, low: a subscribe while the Registry restarts returns `{:error, :session_not_found}` for a running session and removes the old subscription with no lost signal | Documented as a hole: a partition crash is a bug, and a retry is more code than the window is worth |
| Not reproduced: a pid that the node reuses can be killed through a stale entry | Reduced by the pruning of dead entries; documented as a hole |
