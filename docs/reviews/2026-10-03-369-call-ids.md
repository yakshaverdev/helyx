## Invariant

The session is the one owner of the Helyx tool-call ids. A tool request whose call id is open in the current turn (it runs on the hands or waits) stops the provider process through the generic bad-action path. A request whose id the turn already answered runs again. Entry points: `Helyx.Session.Stream.check/1` and `Helyx.Session.Server.Tools.request/3` in the session; `Helyx.HarnessIO.admit/3` through `Codex.Tools.call/3` and the Claude Code MCP `tools/call` in the providers. The providers keep only the answer for a call with no Helyx turn and the check that a call maps to a tool use. The provider event is `{:user_message, steer_id}`, and the session appends its own checked steer text.

Accepted: a program that reuses a call id. No real program reuses an id; the reuse check of #203 came from a design rule. If a program reused an id while the provider still held it open (in the window between the session's answer and the provider's write), the Codex provider would overwrite its `requests` entry and stop at the second result (`Map.pop!`), and the Claude Code provider would leave the first MCP request unanswered until the turn ends. A Claude Code retry with the id of a withdrawn call that still runs now stops the provider; before, the provider answered "used before". No run shows either case.
