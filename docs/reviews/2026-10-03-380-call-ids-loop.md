# Review: the Loop uses the model call id as the request id (#380)

Date: 2026-10-03. Base: `origin/master` (`591fb5d`). Scope: `lib/helyx/provider/loop.ex`, its test, `test/helyx/session/loop_test.exs`, `test/support/interfaces.ex`, and `docs/features/one-provider-path.md`.

First commit: target 2 of #380 only (the second commit, below, does targets 1 and 3). Target 1 (remove `{:rejected_tool_call, ...}`) was not in this commit: the session's rejection path carries only the integer reason of `Stream.check/1`, so a bad-JSON call cannot get its "tool call not run" result there without new code. The orchestrator asked to stop and report before any new code, then chose option d (below).

## Invariant

`Helyx.Provider.Loop` sends each `tool_request` with the model's call id and keys the results by that id. Every result reaches the transcript once, in call order, under its real call id. A call id that repeats in one model message ends the provider process with `{:bad_stream_event, {:tool_call, call}}` in `call/3`, whether the session answered the first call or not. Entry points: the stream events `tool_call` and `rejected_tool_call`, `Loop.request/3` with `tool_result`, and the dispatch at `done`. Accepted (#369): a call id that repeats across two messages of one turn is checked only by the session's open-id check.

# Second commit: one rejection path for a bad tool call (targets 1 and 3)

Base: the first commit (`0938955`). Decision of the orchestrator (option d): arguments that do not decode to a JSON object come as their raw text in a normal `tool_call` or `tool_request`; `Helyx.Session.Stream.check/1` gives the call `%{}` and the rejection reason `the arguments are not a valid JSON object`, next to the integer reason; the session's existing rejection path answers it. `{:rejected_tool_call, ...}` is removed from the contract, the Loop, OpenAI, and the test support. Arguments that are neither a map nor a binary stay a malformed event.

## Invariant

A call whose arguments are not a JSON object gets `tool call not run: the arguments are not a valid JSON object`, the turn goes on, and no transcript entry, session file entry, or tool result holds the raw text. Core's error for a malformed call or request and the helper's error for a repeated call id name the call with `%{}`. Accepted: an error that holds a provider value as sent (the OpenAI `bad_chunk`, a malformed event that is not a `ToolCall` struct) can hold the raw text, within the provider's limits. Entry points: `Stream.check/1` for `tool_call` and `tool_request`, `Helyx.Provider.Loop.call/2` (repeated call id), and `Helyx.Provider.OpenAI.Events.decode_arguments/2`. Before the check the raw text is bounded only by the provider: 10 MiB of tool call bytes for OpenAI.

Two findings landed on one mechanism (raw text in an error), so the premise was checked first: the orchestrator asked that the raw text be bounded before it enters the transcript or the tool result. A generic error that holds a provider value as sent (`bad_chunk` since #368, `bad_action`, a malformed event) holds the model's own output within the provider's limits (1 MiB per SSE line, 10 MiB of tool call bytes), as it holds every other provider value. The invariant was narrowed to that, and the docs and the checklist say so. The two cheap fixes of round 1 stay, because the common paths (a Core-checked call or request, a repeated call id) then name the call with `%{}`. No reproduced defect under the stated invariant, so the loop ends.
