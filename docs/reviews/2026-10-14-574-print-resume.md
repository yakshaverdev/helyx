# Review: #574 Print mode continues a session

Invariant: `-p` combines with `--session <id>` and with `--resume` and continues that session through the resume path of the TUI (`CodingAgent.run/1` with `resume:`), with the output, the stderr lines, the signal and halt rules, and the exit status of #491. Every stderr line of print mode gets the clean pass and the 4,000-byte cap in its one writer (`Print.stderr/1`), and the session line names the resumed id, which is the name of the session file.

Entry points: `CodingAgent.CLI.main/2` (the conflict table, `command/3`, `print/2`, `run_cwd/2`) and `CodingAgent.Print.run/2` with `stderr/1`.

Accepted: two processes on one session (no writer lock, ticket 579; the feature doc states the ceiling), and every hole that `docs/features/print-mode.md` states. `--resume` takes the newest session file of the folder whatever its name (`Helyx.Session.File.Scan.most_recent/3` has no id check, while `list/2` and `find/2` have one); print mode cleans the line, and the Core check is a follow-up for the owner.
