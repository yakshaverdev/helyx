# Review: remove the notice stream event; one scrub (#383)

Date: 2026-10-03. Base: `origin/master` (`800bd63`). Scope: `lib/helyx/interfaces/provider.ex`, `lib/helyx/interfaces/event.ex`, `lib/helyx/provider/loop.ex`, `lib/helyx/session/stream.ex`, `lib/helyx/session/provider_process.ex`, `lib/helyx/session/hands.ex`, `lib/helyx/session/server.ex`, `lib/helyx/session/server/record.ex`, `lib/helyx/data/message.ex`, `plugins/bundled/lib/helyx/watchdog.ex`, `plugins/bundled/lib/helyx/harness_io.ex`, `plugins/bundled/lib/helyx/tui/view_model.ex`, their tests, and three feature docs.

## Invariant

A provider stream event enters Core only through `Helyx.Session.Stream.check/1`, which `Helyx.Session.ProviderProcess` calls. The removed provider event `{:notice, text}` is a malformed event like any other unknown event: the provider process stops and the turn fails. Every `done` and `error` terminal leaves `check/1` with the integer cap applied once, and `ProviderProcess` sends it as it is. Tool result text from the hands and from a provider `tool_result` is made valid UTF-8 by one function, `Helyx.Message.scrub/1`. Every harness error text (`HarnessIO.cap_error/1`) and every failed watchdog start reason is cut to one plugin bound of 2,000 bytes, `@reason_max_bytes` of `Helyx.Watchdog`. The session's own `:notice` client event stays, with fixed texts. Accepted hole, unchanged: a provider that raises or exits with a huge integer in its reason makes digit text in its crash report before the cap (`coding-agent.md`).
