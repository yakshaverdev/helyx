# Review: one path ends a turn (#432)

Date: 2026-10-04. Base: `origin/master` (`249ffc2`). Scope: `lib/helyx/session/server/wait.ex`, `records.ex` (was `messages.ex`), `events.ex` (was `record.ex`), `turn_loop.ex`, `server.ex`, `steering.ex`, `lib/helyx/session/transcript.ex`, `stream.ex`, `session.ex`, `lib/helyx/data/message.ex`, `lib/helyx/interfaces/event.ex`, `provider.ex`, and the docs that stated the old rule.

## Invariant

`Wait.finish/2` is the one path that ends a turn (done, abort, failure), and `Records.finish/2` closes an open partial message so that it always joins the transcript and the session file: one with text only gets the stop reason `:aborted` or `:error` and its `message_end` has the reason in `error`; one with a tool call gets `:tool_use` and its calls start. At an abort or a failure no partial, or a partial with no block, stores no message (the second still gets its `message_end`); `done` keeps its message, an empty one too. Then each open call gets its `aborted` result. Only the session gives `:aborted` and `:error`: `Helyx.Session.Stream` rejects them from a provider. `Transcript.resumable/3` gives no resume id when the last assistant message has one of them.

## Owner decisions (Codex for the owner, 2026-10-04)

The branch was rebased on `origin/master` with #434, #435, and #439. Conflict: one line of `docs/features/session-stream.md` (both sides changed the sentence on the stream checks; both changes kept). The test of #439 for the 1,025th block expected the old rule (a text-only partial not in the transcript); it now expects the cut message with stop `:error`. The new persistence test uses the subscribe reply of #434.

1. Resume, changed. `Transcript.resumable/3` reads the actual last assistant message and gives nil when its stop is `:aborted` or `:error`: the provider session may not have the partial reply that the transcript stores, and an older message does not show that it has it. `last_uncut_assistant/1` is deleted; `last_assistant/1` is back. The Claude Code test "a fresh session aborted before its first message is not resumed after a restart" passes unchanged. New test in `transcript_test.exs`.
2. Order, accepted. Exception to the ticket line "The events keep their order and fields": `Wait.finish/2` has one order for every outcome. It kills the prepare Task, closes the records (`message_end`, the `aborted` results), ends the steers (`steer_unconfirmed`, `queue_update`), drops the queues at an abort or a failure, answers the open tool requests with `aborted`, emits `turn_end` (at `done`) and `agent_end`, and then sends the cleanup request to the hands and the interrupt. Before, an abort or a failure ended the steers and sent the cleanup request before the record close.
3. Empty message at `done` with no partial, accepted as is: it joins, because `turn_end` carries it.
4. Empty partial at an abort or a failure, changed. An open message with no block (a first event over a bound opened it) gets its `message_end` with the stop reason and `error`, and it does not join the transcript or the file. New test in `stream_events_test.exs` (model `first_over_bound`).
5. `Helyx.Provider.Loop` drops a `done` with no content while a steer is held, before the stream check: left as it is; the coordinator logs it in the devlog.
