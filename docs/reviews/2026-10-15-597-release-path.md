# Review: #597 A command of the agent runs the user's erl, not the erl of the release

Invariant: after `CodingAgent.CLI.main/1`, the only entry of the release launcher and of `mix helyx`, every command that the agent starts inherits no `RELEASE_*`, `ROOTDIR`, `BINDIR`, `EMU`, or `PROGNAME` variable. In a release (`RELEASE_ROOT` set), its `PATH` does not start with `RELEASE_ROOT` or a folder in it, so a child `mix` or `elixir` runs the user's own `erl`. Outside a release, `PATH` stays.

Files: `apps/coding_agent/lib/coding_agent/cli.ex`, `apps/coding_agent/test/coding_agent/cli_test.exs`, `docs/features/local-release.md`.

Design: the triage decision names the release folders at the start of `PATH`. The code drops the leading entries in `RELEASE_ROOT` and does not rebuild the prefix of erlexec from `BINDIR` and `ROOTDIR`. Under mise, the user's own `PATH` starts with `<erlang root>/bin` (measured), so the string `BINDIR:ROOTDIR/bin:rest` is ambiguous outside a release, and erlexec puts only `BINDIR` in front when `PATH` already holds the root (`erlexec.c`, OTP 28.1, lines 553-620).

Probe (author, and the spec and failure-path agents): a release built from this tree in `/tmp/helyx597`, started under `mise exec` with the entries of the orchestrate release removed from `PATH`. After `main/1`, a child `elixir -e 1` exits 0; without the cleaning, it fails with `cannot get bootfile '/private/tmp/helyx597/releases/ad87a11-dirty/bin/start.boot'`. The unit tests fail with the `PATH` cleaning removed (2 of 10).
