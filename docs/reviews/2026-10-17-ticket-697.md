# Review of the context % after a compaction (#697)

The change: at a `:compaction` event, the live context estimate of the TUI takes `tokens_after` with zero bytes after it, or nil tokens when `tokens_after` is nil, so the footer shows no % until the next usage with `context_tokens`. The window, the model, and the session totals stay; a nil estimate stays nil. The rule is `Helyx.Session.Totals.compacted/2`, next to `context/2`, and `Helyx.TUI.ViewModel` calls it. It builds on #698 (the commit before it on this branch).

## Accepted holes

- A new snapshot, after a resume or a re-subscribe in a live session, folds the messages only, so it shows the estimate of the last usage before the compaction. The ticket puts the estimate of a resumed snapshot out of scope. The TUI subscribes once to each session; a wire client that reconnects before #659 takes a new snapshot, so after a Claude Code compaction its % goes from 4 % back to the old value until the next usage. A fix keeps the compacted estimate in the session state; it has no ticket yet.
- A summary compaction always gives `tokens_after: nil`, so after a summary the % hides until the next usage.
- A compaction before any usage leaves the estimate nil: there is no window to show a % with.
