# Review: a harness session with no stored program state (#750)

Scope: the working tree against the branch base `ed35afe4`. Files: `lib/helyx/session.ex`, `lib/helyx/session/input.ex`, `lib/helyx/session/sync.ex`, `lib/helyx/session/server/{state,open,calls,prepare,summary,turn_loop}.ex`, `lib/helyx/interfaces/provider.ex`, `plugins/bundled/lib/helyx/harness_io.ex`, the Claude Code and Codex provider modules (`claude_code.ex`, `claude_code/{program,state}.ex`, `codex.ex`, `codex/{check,program,state}.ex`), their tests, the feature doc `docs/features/harness-no-state.md`, and the docs `long-lived-harness.md`, `server-management.md`, `claude-code-stream-json.md`, `codex-app-server.md`.

Invariant: with the provider option `persist: false`, given through the session option `:provider_opts`, no harness program of the session stores or resumes a conversation. Claude Code launches with `--no-session-persistence`. Codex starts each thread with `ephemeral: true`, and only an answer with `thread.ephemeral` `true` goes on. The provider gives no `:resume_id` event. A prompt change starts a fresh harness session with the replay. `init/3` with a resume id fails with `:no_state_resume`. A Claude Code compaction fails at once.

## Probes of the author

- `claude --help` of 2.1.302 lists `--no-session-persistence`, "only works with --print". The Agent SDK code in the binary adds the flag with the stream-json flags and no `-p` (static read of the binary).
- `codex app-server generate-json-schema --out <tmp>` of codex-cli 0.163.0: `ThreadStartParams.ephemeral` (boolean or null), `Thread.ephemeral` ("should not be materialized on disk"), no `ephemeral` in `ThreadResumeParams`.
- The meter test fails when `Program.ensure/3` keeps the old meter (one line changed, then restored).

## Simplify

One agent (the first one stopped on the account's usage limit and changed nothing; it ran again). Applied: `HarnessIO.compaction_failed/2`, which `no_history/1` and `Program.no_compaction/1` share; `ClaudeCode.id()` in place of the literal id; `init_opts/3` as a `do` block; comments in `input.ex`, `claude_code.ex`, and `codex/program.ex` (the `params/1` comment was wrong: `thread/resume` shares `params/1`).
