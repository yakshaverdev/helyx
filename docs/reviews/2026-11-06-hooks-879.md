## Owner decisions after the first commit

## Owner review of the second commit

One accepted hole broke a written rule, so it is a defect: the session's record of a Task came from the hands and the Task's ask from the Task, two senders with no order (`AGENTS.md`, #592). Fix: the session sends the Task its go after it handled the record (`Asks.asker/4`); the Task waits for it before any plugin code runs (`Helyx.Session.Ask.await_go/0`). Test "a hook Task runs only after the session stored its record and let it go" suspends the session between the record and the go; it fails when the hands send the go.

The rebase onto master brought the system prompt entry (#553), which left `lib/helyx/session/file.ex` at 400 lines; `append_hook/2` took it over the limit. The `FileLength` list only shrinks, so the hook entry goes through the plain `append/2` of the file (public, `@doc false`); `Helyx.Session.HookEntry` owns its shape.
