# Review: one decode function that never raises, and a Credo check for raw JSON.decode (#792)

Scope: the working tree against the branch base `7e937736`. Files: `lib/helyx/json.ex`, `credo/json_decode.ex`, `.credo.exs`, the call sites in `lib/helyx/session/file/reader.ex`, `lib/helyx/session/file/scan.ex`, `plugins/bundled/lib/helyx/harness_io.ex`, `plugins/bundled/lib/helyx/model_info/catalog.ex`, `plugins/bundled/lib/helyx/provider/openai/events.ex`, `plugins/bundled/lib/helyx/transport/web_socket/frame.ex`, `apps/coding_agent/lib/coding_agent/serve.ex`, the tests `test/helyx/json_test.exs` and `test/credo/json_decode_test.exs`, `docs/agents/review-checklist.md`, and `docs/features/wire-protocol.md`.

Invariant: every JSON decode of outside data in `lib/` code goes through `Helyx.JSON.decode/1`, which gives `{:error, :system_limit}` in place of the `SystemLimitError` raise of `JSON.decode/1`, and each boundary keeps its existing answer to bad JSON. The Credo check `Helyx.Credo.JSONDecode` reports a call written `JSON.decode` or `JSON.decode!`, of any arity, in a `lib/` folder, except in `Helyx.JSON`.

## Decisions

- `Helyx.JSON` is `@moduledoc false`: plugins already call `@moduledoc false` Core modules (`Helyx.Session.Stream.check/1`), and a public module would add to the extension surface.
- `JSON.decode/2`, which the ticket names, does not exist in Elixir 1.19.5: `JSON` exports `decode/1`, `decode/3`, and `decode!/1`. The check reports every arity, so `decode/3` with default decoders is not a hole. The one `decode/3` call, `Helyx.Transport.WebSocket.Frame.json/2`, has an inline disable that the check explanation names: its `integer/1` decoder bounds the digits to 1,024 (#787), so it does not raise.
- The #782 rescue was gone on the base: `47639aaf` (#787) put the bounded decoders in its place. The four rescues of #786 are replaced. Calls with no rescue on the base, where a cap keeps the integer out, go through `Helyx.JSON.decode/1` too, because the check reports them: `Scan.head/1` and `Scan.message/1` (65,536 bytes), `OpenAI.Events.data/2` (1,048,576 bytes), and `CodingAgent.Serve.read_file/1` (4,096 bytes).
- The shipped models.dev snapshot matches `{:ok, json}`: a snapshot that does not decode is a bug, and crashes, as `JSON.decode!/1` did.
- `Helyx.JSON.decode/1` rescues only `SystemLimitError`. A probe of about 26 shapes (integers over the limit, negative, inside an object; float overflow, large exponents and mantissas; 1,000,000-deep nesting; bad UTF-8; lone surrogates; empty text) found no other raise for a binary input. A non-binary input raises `FunctionClauseError`, as in `JSON.decode/1`; every caller passes a binary.

## Simplify

One agent. Applied: the check explanation cites the tickets once and says "five boundaries"; the `is_list(args)` guard is removed, as the arguments of a remote call are always a list. Rejected: a `.ex$` suffix in the path regex (`lib/` covers every folder of the ticket, as in `Helyx.Credo.FileLength`); changes to the `else` clauses of the call sites (each is a catch-all).
