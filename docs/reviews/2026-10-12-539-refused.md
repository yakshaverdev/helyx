# Review: #539 A filtered or refused answer stops with `:refused`

Invariant: a provider that reports a filtered or refused answer (an OpenAI Chat Completions `finish_reason` `content_filter`, parsed by `Helyx.Provider.OpenAI.Events`, and a Claude Code success result whose `stop_reason` is `refusal`, read by `Helyx.Provider.ClaudeCode.Turn.terminal/2`) ends the turn with the one new stop reason `:refused`, which `Helyx.Message.stop_reasons/0`, `Helyx.Session.Stream.check/1`, and the session file codec accept and round-trip with no format version change (an older reader decodes it as nil and keeps the content). The TUI view model adds one `{:stop, reason}` cell after an assistant message and its tool cells only for `:max_tokens` and `:refused`, by the same rule on the live fold and in `from_snapshot/1`, drawn as a notice. Accepted holes: Codex maps nothing to `:refused` (out of scope, no known wire value), and whether the OpenCode gateways forward `content_filter` from an upstream model is not observed.

## Decision (A) of the orchestrator

Accepted as a limit; the steer protocol does not change. A stop reason that arrives while a steer waits is lost, and the turn continues with the steer. Reason: the hole needs a refusal or a token-limit stop while a steer is in flight. The user has already sent new input, and the turn goes on with it, so the missing line does not change the next step of the user. Option (B), keeping the stop reason across a steer, changes the harness steer path, which #539 does not cover and which has had several race fixes; with no evidence that users hit this case, it is not worth the risk.

The fix after the decision: the `Helyx.Provider` moduledoc, `docs/features/coding-agent.md`, and the "Current limits" of `docs/features/session-lifecycle.md` state the one rule for both paths (2.1). The session test of malformed stream events gets two rows, a provider `done` with `:aborted` and with `:error` (2.2). The `Helyx.Message` comment says that a partial with a tool call closes with `:tool_use` (2.3). The fix touches two code files (comments only): a full round.
