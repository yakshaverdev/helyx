# Review: #478 Helyx owns the shell

Invariant: a model on `claude-code/*` or `codex/*` starts a process only through the Helyx `bash` tool, where the hands give it its abort, its output bound, and its tool events. `Helyx.Provider.ClaudeCode.init/3` starts `claude` with `--disallowedTools=Bash,Monitor` (sub-agents too), and `Helyx.Provider.Codex.init/3` starts `codex app-server --disable shell_tool --disable unified_exec`. Both send the session's Helyx tools except `read`, `edit`, and `write` (`Helyx.HarnessIO.harness_tools/1`), and a call of a tool that the program was not given gets `the call does not map to a tool use` (round 2).

Accepted holes: the harness keeps its own file tools and its other built-in tools (web, sub-agents, LSP, the user's hooks). The Codex `command_running` check stays as a safety bound for a command that the program runs by itself. A Codex thread stored with the old tool set starts fresh with the replay. A per-product option for the harness shell is out of scope, and approvals stay `accept` (#503).

Codex probe (design step 3): passed. `codex/gpt-5.6-luna` with the shell off read the files and ran the test with the Helyx `bash`, changed the file with `apply_patch`, and the turn ended `:done` with no `commandExecution` item (`docs/research/harness-shell-off.md`).
