# Review: the attach client, slice 1 of the TUI attach (#662)

Scope: the working tree against the branch base `c9938dc4`. Files: `apps/coding_agent/lib/coding_agent/attach.ex`, `apps/coding_agent/lib/coding_agent/serve.ex`, `plugins/bundled/clients/tui/lib/helyx/tui/wire.ex`, `plugins/bundled/test/support/wire_client.ex`, `apps/coding_agent/test/coding_agent/attach_test.exs`, `plugins/bundled/test/helyx/tui/wire_test.exs`, `docs/features/tui-attach.md`.

Invariant: `CodingAgent.Attach.connect/1` and `Helyx.TUI.Wire.connect/4` attach a client to the `helyx serve` of a data folder only while its lock is held and its server file is valid; a free lock or a missing data folder is no server, and the client never writes or removes the server file; every failure before `welcome` but `refused` and a contract break after a valid `101` is a server that is starting, tried again every 100 ms with no attempt after 5,000 ms; `refused` and a contract break end at once with one line; no error holds the token; every read and wait has a bound.

## Decision

- The ticket is split into five slices (`docs/features/tui-attach.md`, "Slices"). Slices 2 to 5 are #806, #807, #808, and #809, each ready for an agent and blocked by the slice before it. This commit builds slice 1 only; nothing calls it yet.
- The WebSocket client is written on `:gen_tcp`, as the test client of the transport is: no new dependency. The frames are decoded with the codec of the transport (`Helyx.Transport.WebSocket.Frame`), so the client has the decode bounds of the server.
- The read of the server file is one function for a second start and for a client (`CodingAgent.Serve.read_file/1`).

## Simplify

One agent. Kept: the fake server helpers share the mask and the length code; `fake_challenge/1` returns its nonce; `result/2` has a clause for `:broken`; `frame/2` is a `with`; the renames `error_text/2`, `test_lock/1`, and `open/5`. No behaviour change.

## Accepted holes

- The lock test of a client holds the lock for the few milliseconds of a take and a release: a `helyx serve` that starts in that window exits 1. Open, ticket #808.
- The read of the server file checks the type, then opens it: a FIFO put in place between the two blocks the open. Open, ticket #777.
- A send of the handshake has its own `send_timeout` of the connect timeout, outside the one deadline of the reads; the two sends are under about 250 bytes and did not block in any probe.
- No committed test proves that no attempt starts after 5,000 ms, or that no port message stays in the mailbox of the caller: probes of both rounds.
