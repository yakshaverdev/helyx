# Review: #591 Print mode waits for its background runs

Invariant: print mode returns only when the session is idle with no open background run whose end can still open a turn. An open run is a start answer with no end message in the transcript or the events. Print mode then prints the answer of the last turn and returns its status. A held end (`queue_update` or snapshot `held` above 0) never opens a turn in print mode, so with an open run print mode prints the last answer, writes one stderr line, and returns 1. SIGTERM and SIGHUP keep 143 and 129 during the wait.

Entry points: `CodingAgent.Print.run/2` (its `wait/2` and `settle/2`), `Helyx.Session.Queue.counts/1` (the new `held` count), the `queue_update` event and `Helyx.Session.Snapshot` `queue`, and the TUI `Helyx.TUI.ViewModel`, which keeps only the steers and the follow-ups.

Accepted (the "Accepted holes" of `docs/features/print-background-wait.md`):

- A foreground result whose text opens with the exact start line counts as an open run; print mode waits until a signal.
- A turn that the provider starts by itself (#240) clears a hold; print mode can exit before that turn.
- A hold with no held end yet holds print mode until the next end arrives, up to the `timeout` of its run.
- Print mode reads the start and end texts of `docs/features/background-bash.md`; a change of those texts changes print mode too.

## Owner change (2026-10-15): Core counts the live runs

After rounds 2 and 3, the owner decided that print mode reads no text, tool name, or arguments to count the live runs. Core counts them. The hands send the start answer as `{:started, text}` (`hands.ex:192`, no new line). The session server adds 1 to `running` in `Helyx.Session.Queue` and delivers `{:ok, text}`. Each `{:background_end, text}` subtracts 1. `queue_update` and the snapshot `queue` carry `running`, `held`, and `waiting`. Print mode waits while `running + waiting` is above 0 and `held` is 0. The text parser and its pattern are gone from print mode. The code of rounds 2 and 3 stays on the branch `ticket/591-bg-call-wip`, which is not merged; `Background.id_and_status/1` is not on this branch.

`waiting` goes beyond "running next to held". An end that waits for a turn with no hold (no steer room, a compaction), and an end that a turn sent and no `user_message` took, can still open a turn or come back after `turn_end`. Without `waiting`, print mode would exit 0 at that `turn_end` and lose them.

Invariant given to the reviewers: print mode waits exactly while a background run is live or an unheld end waits, under every provider (native, Claude Code, Codex), and each wait ends at the run's end, its timeout, the stop, or a signal. Each start adds 1 and each end subtracts 1, exactly once, on every path. Base: `2da8649`. The /ship limits were past; the owner allowed one full round, then a reduced round if that round fixed a defect.
