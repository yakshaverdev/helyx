# Review: #591 Print mode waits for its background runs

Invariant: print mode returns only when the session is idle with no open background run whose end can still open a turn. An open run is a start answer with no end message in the transcript or the events. Print mode then prints the answer of the last turn and returns its status. A held end (`queue_update` or snapshot `held` above 0) never opens a turn in print mode, so with an open run print mode prints the last answer, writes one stderr line, and returns 1. SIGTERM and SIGHUP keep 143 and 129 during the wait.

Entry points: `CodingAgent.Print.run/2` (its `wait/2` and `settle/2`), `Helyx.Session.Queue.counts/1` (the new `held` count), the `queue_update` event and `Helyx.Session.Snapshot` `queue`, and the TUI `Helyx.TUI.ViewModel`, which keeps only the steers and the follow-ups.

Accepted (the "Accepted holes" of `docs/features/print-background-wait.md`):

- A foreground result whose text opens with the exact start line counts as an open run; print mode waits until a signal.
- A turn that the provider starts by itself (#240) clears a hold; print mode can exit before that turn.
- A hold with no held end yet holds print mode until the next end arrives, up to the `timeout` of its run.
- Print mode reads the start and end texts of `docs/features/background-bash.md`; a change of those texts changes print mode too.
