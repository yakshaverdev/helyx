# Review: #489 List earlier sessions and resume one by id

Invariant: the list and the newest-session resume leave out a session file whose head of 65,536 bytes is the whole file and holds no message, and nothing changes in how a session is written. A session id is checked against the 12-character id format before any path is built. A session resumed by id runs in the folder that its header names, which must be an absolute path to an existing directory. Every text from a session file is cleaned and cut by code points before it reaches the terminal. Entry points: `CodingAgent.CLI.main/1` with `--list`, `--all`, and `--session`, `Helyx.Session.File.Scan.list/2` and `find/2`, `Helyx.Session.File.resume/3` with `:id`, and `Helyx.Session.resume/2` with `:id`.

Out of scope (owner, 2026-10-13): the TUI part is #551.

Accepted:

- A file of 65,537 bytes or more with no message in its head is listed with an empty prompt, and the newest-session resume can take it.
- The model on a list line is the model of the header, not the current model.
- The lookup of an id runs twice for one start (the command line, then `Session.File.resume/3`). A file that changes between the two reads gives the error of the second read. The cost is one wildcard and one head read.
- A cut by code points can leave a combining mark without its base at the end of a field.
- `--list --all` stats every session file before it takes the 256 newest, as the newest-session resume of one folder did before.
