# Review: #487 Markdown in assistant replies

Invariant: the text of an assistant message renders as Markdown through `Helyx.TUI.Markdown.rows/2`, its one entry point, called from `Helyx.TUI.Transcript` for assistant text blocks only. The text of every row is a row of the width rule (`Helyx.TUI.Wrap`) on the sanitized plain text, with a prefix only when the whole row fits, so the width and scrollback bounds hold. Any model text renders without a crash, and a line costs time linear in its length. Accepted holes are in `docs/features/coding-agent.md`, "TUI": an unclosed fence is plain text also in a finished reply, emphasis does not cross a line, no block quotes, tables, or rules, a link text shows as written, and the rows are parsed on each frame (no line cache, as before).

`ExRatatui.Widgets.Markdown` was checked first: it renders `tui_markdown` into a `Paragraph` with ratatui's own wrap and returns no rows to Elixir, so the transcript cannot count its rows. An own renderer on top of the width rule was built instead.

## Round 1 (full)

Simplify: `Wrap.sanitize/1` made public and reused in place of a copy (reuse); delimiter text from the run, no `size/1`; the link tuple by a match; `_rest` for the left segments (simplification); a fast path for a line with no sign, and an ASCII clause before the word regex (efficiency). Skipped: one hang helper for the user bar and the list prefix (touches the user row of #483 while other tickets change the TUI); a `{grapheme, tag}` wrap in `Wrap` that would delete `align/2` (changes the shared width rule); a row cache for closed messages (the transcript has no line cache by design; a design decision).

## Round 2 (full)

Fix of round 1, counted from its diff: 104 lines added plus removed in 2 code files (`markdown.ex`, `wrap.ex`); it adds functions and makes `Wrap.sanitize/1` and `Wrap.line_rows/2` public, so the round is full.

Simplify: an ASCII fast path for the grapheme pass (efficiency); `pairs?` in place of a variable that shadowed `closes?/2` (simplification). The first form of `whole/1` read the whole segment again at each boundary, which was quadratic for a letter with thousands of marks in separate emphasis (20 KB: 2,044 ms); replaced by one pass over the line (`cut/4`, `grapheme_end/2`; 20 KB: 54 ms). Skipped: drop `sign?/2` (it saves three regex calls on most lines: 5,000 plain lines went from 40 ms to 13 ms with it and the per-line wrap); a `Wrap.fits?/2` shared with the user row (touches #483 code); one span helper in the transcript for the same ExRatatui rule (follow-up).
