# Review: `--session` runs the tool checks before it looks for the session (#765)

Scope: the working tree against the branch base `dcca6b86` (`origin/master` at the start; master moved to `440a69b0` with #766 during round 1, so round 2 used `git diff HEAD`). Feature docs: `docs/features/server-management.md`, "Order of the checks" and "Replaced mechanism" item 6; `docs/features/session-list.md`, "Folder".

Invariant: `helyx --session <id>`, with and without `-p`, makes no check of its own before Core: it starts Core and resumes the id with no `:cwd` (`Helyx.Session.resume/2`), so the tool checks run before any read of the sessions directory and a failed tool check prints the same line as a start. The find errors keep `not a session id: "<id>"` and `no session "<id>"`. After the open, `CodingAgent.run/1` reads the folder from `Helyx.Sessions.list_live/1` and rejects a folder that is not an absolute path to a directory with `not a directory: "<folder>"`. Accepted holes: that rejection comes after the open (the lock file stays, a missing final newline is added); a session that does not answer the live list in 5,000 ms gives `:session_not_found`.

## Reproduction

`apps/coding_agent/test/coding_agent/cli_test.exs`, "--session with no perl on PATH prints the tool error of a start", on the code before the fix: `--session <id>` of a saved session printed `no session "<id>"`, and a start printed `could not start the agent: the bash tool is not available: perl not found: ...`.

## Decision

The ticket names `Helyx.Sessions.resume/2`. The CLI calls `Helyx.Session.resume/2` with `:id` and no `:cwd`. That is the same call: `Sessions.resume/2` adds only the `:sessions_dir` of the Core, and `CodingAgent.run/1` starts Core with no `:sessions_dir` and passes the folder to each call, as for a start. The header-folder rule of #758 is in `Session.resume/2`. `Helyx.Session` and `Helyx.Sessions` do not change (#735 changes them at the same time).

The folder rule of the owner decision "Folder" (absolute, exists) stays in the client: Core does not check that a given `:cwd` exists, and #758 gave the header folder the cwd check of a start. A Core check in `pick/3` would make a header folder stricter than a given one. That is a question for the owner (see the report of #765).
