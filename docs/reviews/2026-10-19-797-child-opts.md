# Review: a child session gets the provider options of its parent (#797)

Scope: the working tree against the branch base `99fcfe49`. Files: `lib/helyx/session/server/tool_runs.ex`, `lib/helyx/interfaces/tool.ex`, `lib/helyx/session/hands.ex`, `plugins/bundled/lib/helyx/tool/agent.ex`, `plugins/bundled/test/helyx/tool/agent_test.exs`, `docs/features/agent-tool.md`, `docs/features/harness-no-state.md`.

Invariant: a child session that `Helyx.Tool.Agent` starts gets, as its `:provider_opts`, exactly the `:provider_opts` of the parent session process that runs the call, from its start or its resume. `Helyx.Session.Server.ToolRuns` puts them in the call context (`Helyx.Tool.context/0`), and the tool gives them to `Helyx.Sessions.start/2`, which checks them again.

## Decision

- The options travel in the call context, the one channel from the session to a tool call (`docs/features/agent-tool.md`, decision 3). Core names no key of them and gives every tool the same map; a tool that does not read the key is unchanged.
- The test provider `Report` is nested in the agent test: the bundled project does not compile the root `test/support`, where `Helyx.Test.SummaryProvider` reports `init/3` the same way.

## Proof (author)

- Red: before the change, the new test failed: "Assertion failed, no matching message after 30000ms" for the `{:init, child, opts}` of the child.
- Mutation: with the line `provider_opts: context.provider_opts` removed from `agent.ex`, the test failed with the same assertion (`1 test, 1 failure`); the line is restored.
- Repeat: the test file 3 times after the round-1 fixes, `16 tests, 0 failures` each.

## Simplify

One agent. It replaced the `Report` provider with a read of the child's session state (`:sys.get_state`). Reverted: the ticket's acceptance names the child's provider `init/3`, and the state read tests an inner field. Kept: the rewrap of three docs, and two removed sentences in the feature docs that repeated a decision.
