# Review: #427, Codex interrupt id and composer paste text outlive what they track

Branch `ticket/427-plugin-leaks`, base `origin/master` `10b0775`.

Invariant: at the Codex provider's `turn/completed` (`end_turn/2`), a sent `turn/interrupt` is answered and its request id leaves `due`, so a later answer with that id takes the unknown-id drop path of `Check.malformed/2`, while an interrupt error that arrives before `turn/completed` still answers the interrupt with the error. In `Helyx.TUI.Composer`, Backspace or Delete that removes a marker also removes its `pastes` entry, and a marker id comes from `count`, which only grows and resets in `clear/1`, so no marker id repeats before the composer is emptied. Entry points: the Codex program lines, and the key and paste events of `Helyx.TUI.handle_event/2`. A key with a modifier other than Shift never reaches the composer.

## Input paths probed (`/implement`)

- `due` entry of a sent `turn/interrupt`: written by `open/2`, removed by its answer (`dispatch/2`) or now by the turn's end. A later answer has no due id: `Check.malformed/2` returns nil and the last `dispatch/2` clause drops it. Before, it reached `answer("turn/interrupt", _, state)`, which also did nothing, so no visible behaviour changes.
- A marker leaves the composer text only through `cut/4` on Backspace or Delete. Every other key first leaves the marker (`out_of_marker/1`). Ctrl and Alt keys do not reach the widget (`Helyx.TUI.handle_event/2`), and `key/2` sends `[]` modifiers, so no undo, yank, or word delete exists. A paste and a key code drop U+0001, so one marker text cannot be in the composer twice.
