# Review: the first Ctrl+C clears the draft, a second within 500 ms quits (#486)

Date: 2026-10-04. Base: `origin/master` fd01e2c for rounds 1 and 2; the rebase onto #484 and #487 and its rounds are in "After the rebase" below.

Invariant (final, after the rebase): in `Helyx.TUI` one `handle_event/2` clause, guarded by `Helyx.TUI.Quit.handles?/2`, hands `Quit` every Ctrl+C key press and, while armed, every other key press and every paste. `Quit.handle/3` answers `:quit` for a Ctrl+C while armed; `{:clear, quit}` for a first Ctrl+C: the TUI clears the composer, and `Quit` arms a ref-tagged 500 ms timer message to the TUI process, with the footer hint `Ctrl+C again to quit` only when `Composer.nothing_to_clear?/1` holds (no text and no draft that Down brings back); and `{:pass, nil}` for another key press or a paste, which disarms and then runs as usual. Only the timer message of the current arm disarms. Accepted holes: a late timer under load makes the window longer than 500 ms; a `repeat` event of Ctrl+C does not quit and a `repeat` of another key does not disarm, which no terminal sends today because ExRatatui pushes no keyboard enhancement flags (so a held Ctrl+C arrives as presses and quits once the key repeat comes within the window); a Ctrl+C on an emptied recalled prompt with an empty draft loses only the recall position.

Rounds 1 and 2 below ran before the rebase, on an earlier shape: a `disarms?` guard, `Quit.ctrl_c/2`, a stricter `Composer.empty?/1`, and a hint in the old status bar.

Checked before the build: `ExRatatui.Event.Key` has `kind` (`press`, `release`, `repeat`), and the native side sets it for every key (`events.rs`). `Composer.clear/1` exists. The orchestrator decided that `Helyx.TUI.Quit` owns the armed state, the window, and the disarm rule, and that `tui.ex` keeps only the calls.
