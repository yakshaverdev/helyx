# Review: #264, test waits and shared test helpers

Date: 2026-09-30. Base: `751af90`. Test-only change.

## Invariant

Every test wait in the root, `plugins/bundled`, and `apps/coding_agent` projects waits for an event (a message, a monitor `:DOWN`, or a trace of the message that the session or the hands received, followed by a synchronous call), or is a bounded poll whose bound is in milliseconds, for state that the BEAM gives no event for (OS processes, port queues, the mailbox of a suspended process). `refute_received` after a synchronous call replaces `refute_receive …, 50` only where the test process itself sent the operation.

Accepted holes, still in the `Process.sleep` grep of "Done when":

- `session_test.exs` `await/3`: 10 ms polls of queue length, memory, the mailbox, and Registry watches. It counts tries, not ms.
- `file_test.exs` sleeps 2 ms twice, so that two headers get different clock times.
- `watchdog_test.exs` sleeps 800 ms inside the grace (#259 works on this file).
- `group_test.exs` sleeps 30 ms in a fake kill run (a tool duration).
- `in_mailbox/3` and `kill_when_queued/3` poll, bounded in ms, as the ticket asks.
- `refute_receive …, 50` stays where another process or a timer sends: the end signal and `subscription_lost` in `session_test.exs`, and `idle_close` in `harness_test.exs`.

Deliberate choices: one gate message, `{:waiting, pid}`, for root and bundled (the ticket text names `{:streaming, pid}`). The shared helpers live in `test/support/shared`, which `plugins/bundled` and `apps/coding_agent` compile through `elixirc_paths`. The TUI Escape test waits for the trace of the session receiving `:abort`, then calls the session, because the Task that sends the abort gives no signal.
