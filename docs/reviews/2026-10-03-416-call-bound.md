# Review: #416, bound the tool calls of the open assistant message

Branch `ticket/416-call-bound`, base `origin/master` `be64978`.

Invariant: the session adds a text delta, a thinking delta, or a tool call to the open assistant message only while the bytes of all of them stay at or under 8 MiB (`@max_message_bytes` in `Helyx.Session.Turn`); a tool call counts as the byte size of the JSON encode of its id, name, and checked arguments, which `Helyx.Session.Stream.check/1` makes for its check in the provider process and carries as `{:tool_call, call, bytes}`, so the session process makes no encode; the count starts again at zero at each close of the message (`message_end`, the first result of one of its calls, a taken steer, the turn end); an event past the bound stops the provider process and fails the turn through `TurnLoop.stop_provider/2` with `{:message_too_large, bytes, 8388608}`, with no truncation and no special handler. Entry points: `Stream.check/1` in `Helyx.Session.ProviderProcess` and the generic `stream_event` clause of `Helyx.Session.Server`. Accepted: one waiting event in the session mailbox has no byte bound in Core; a tool request is not counted by itself, because its call joins the message only through the provider's own `tool_call` event, and the waiting tool requests of `Helyx.Session.Tools` are outside this ticket.

## The size that the check already computed

Before #416, `Stream.tool_call/1` called `Message.encodable?([id, name, capped])`, which made the JSON encode and dropped it. Now `Message.encoded_size/1` returns the byte size of that same encode, and `encodable?/1` calls it. The checked event carries the size, and `Messages.delta/2` passes it to `Turn.add_block/3`. A text or thinking delta passes its `byte_size/1`, as before. Each call is encoded once, in the provider process, as before.

## Changed tests

- `turn_test.exs`: `Turn.add_block/3` takes the size of the event; the test passes it. What it checks is the same.
- `stream_test.exs`: a checked tool call is now `{:tool_call, call, bytes}`; three matches take the third element. One test asserts the size 16 for `["c1","read",{}]`.
