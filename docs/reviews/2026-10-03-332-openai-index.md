# Review: a null or string tool-call index in the OpenAI parser (#332)

Date: 2026-10-03. Base: `origin/master` at `20272cc`. Scope: `plugins/bundled/lib/helyx/provider/openai/events.ex`, `plugins/bundled/test/helyx/provider/openai/events_test.exs`, and the bounds row "Tool call bytes per response" in `docs/features/coding-agent.md`.

## Invariant

In `Helyx.Provider.OpenAI.Events.events/1`, a tool-call delta whose `index` key is present carries an integer from 0 to 10,000; any other value, null included, makes the chunk malformed, and the stream ends with one `{:error, {:bad_chunk, payload}}` and no tool call. Only a missing index takes the implied index. The chunk is the rejected unit, because the parser cannot tell which call a bad index means.

Ticket step 3: Core accepts a `:tool_call` with an empty id. `tool_call/1` in `lib/helyx/session/stream.ex` checks only `is_binary(id)` and `is_binary(name)`. A fix in Core is a separate ticket.
