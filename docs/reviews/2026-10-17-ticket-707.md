# Review: the session cap counts sessions only (#707)

Scope: `Helyx.Core.init/1`, `Helyx.Core.sync_supervisor/1`, `Helyx.Session.Sync.open/1`; `docs/features/server-management.md`, `docs/features/memory.md`.

Invariant: the cap of 64 per Core counts only the session processes under the session supervisor; each memory sync worker, live or draining after its session stopped, runs under the sync supervisor of Core, which has no cap, so a Core with a Memory plugin starts 64 sessions and no session open crashes on `{:error, :max_children}`. Accepted holes: the drains have no count cap (each ends within the 30,000 ms drain bound with at most its queue bound); a kill of the sync supervisor ends sync for the live sessions with no notice. Open: #694, unchanged.
