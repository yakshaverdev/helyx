## Round 1 (full)

- Failure path (reproduced), Codex, spec: an answer marked the ask answered before the network took it, and a refusal, an error reply, or `Unknown` never cleared the mark, so the ask stayed hidden for the run and the user could not send it again (ADR 0006 §4). Fixed: an ask stays hidden only while its answer is pending or after `ok`.
- Failure path (reproduced), Codex, spec: one `saved_more` flag for all `sessions.saved` requests; two "more" clicks, or a refresh and a "more", lost the first page. Fixed: the mode belongs to the request id.
- Codex, spec: an accepted send left its text in the composer, and a second Enter sent it again (`multiline-composer.md`). Fixed.
- Codex: Enter on a multiple-select option added the option under the cursor to the marks; the TUI takes the marks. Fixed.
- Codex: the form went on past an answer that left no room for the later questions, and the user could not go back. Fixed with the reserve rule of the TUI.
- Codex: `Operation::answer` took a `Json::Number` or `Json::Deep` whose text is not JSON, or an integer of more than 100 digits, so a host could send a frame that the server refuses. Fixed with the JSON checks of the core.
- Spec: space always marked an option, also on the Other line; the Other line had no bound; Enter during a turn sent a follow-up, where the TUI steers (Alt+Enter: follow-up); a refused send wrote its line where the next connection state overwrote it; `client-kit.md` said that `sessions.live` goes at the first welcome only. Fixed.
- Standards: one path for an answer (`Input::answer`); `Kind::Approval` carries its model, so the window has no fallback; `Shared::unknown` takes ids; functions that only tests used removed; the note of an ask that the window cannot answer chosen and tested in `ask.rs`.
- Spec: Bounds rows with no test (the request lines, the saved prompt cut, the folder field, the 4 MiB notice). Tests added.

## Round 2 (reduced)

Base: the tree before the round 1 fix. The briefs named the seven invariants of the round 1 fixes.

- Failure path (reproduced), spec: a second answer after a failed one showed the ask again while it was pending, because the failed state of the ask stayed in `Shared`; a session switch could also show a pending ask. Second finding on the hidden state of an ask.
- Failure path (reproduced), spec: two Enter presses before the network thread took the first send sent the text twice, because the composer let go of the text only when the thread reported it taken; a text typed again could lose its start to the prefix take. Spec: an error reply after the send was taken lost the text, where the TUI keeps it. Second finding on the send of the composer.
- Two findings on one mechanism, so round 3 replaces both mechanisms, as the TUI does: `Input` marks a send or an answer pending at the key itself, a pending composer takes no edit and no second send, and only the outcome of that one send settles it (`ok` empties the composer or keeps the ask hidden; a refusal, an error, or `Unknown` keeps the text or shows the ask). The failed state of an ask is no longer stored in `Shared`.
- Failure path (reproduced), spec: `Operation::answer` sized a raw number by its text, but the server encodes it again (`1e2` is `100.0`), so an answer at the bound passed the client and the server refused it. An answer number is now an integer of at most 100 digits; the forms send only strings and booleans.
- Spec: space marked an option of a single-select question; the marks went out in click order; the window drew the marks of the current question on every question; a paste into the Other line kept its new lines. Each now follows the TUI.
- Spec, accepted: the width of the ask panel (420 px) is drawn by `ui.rs`, which has no tests (GPUI).

## Round 3 (reduced)

Base: the tree before the round 2 fix. The briefs named the four invariants of the replaced mechanisms.

- Held: an answer number is an integer, also inside `Json::Deep` (probes: `1.0`, `1e2`, `-1E2`, a fraction 200 deep, `"-"`, `"01"`, `-0`; the size count matches the server's encode for U+2028, DEL, `/`, NUL, ESC); the form rules of the TUI (space on a single pick, marks in option order, marks for each question, a paste on the Other line as one line, the 16,384-byte bound at it, one over, and multibyte); a reconnect and a follow settle a pending send.
- Open, reproduced (failure path, spec): after the network thread stops (`Next::Stop`: the first connect fails, a break of the contract, a refused protocol), `commands.send` fails and nothing settles the send, so the composer stays locked and an answered ask stays hidden for the run. Fix proposed: a send that the channel refuses settles at once as `Failed`.
- Open, reproduced (failure path, spec): at the bound of 16 hidden asks with no settled mark, the eviction drops a pending mark, so its ask shows while its answer is in flight and a second answer can go out. Failed marks of other sessions count toward the bound. Fix proposed: never evict a pending mark; at the bound with every mark pending, the answer is refused (`Busy`, the 16 requests of the client).
- Spec, low: a follow that the network thread applies between the two reads of `Desktop::key` sends an answer under the new session; the server refuses it, and nothing is lost. A tab in a paste on the Other line stays a tab; the TUI makes it two spaces. The outcome queue cap of 64 is above the 34 outcomes that the rules allow before a drain, but no code ties it to the 16 requests.

Both open defects are further findings on the mechanisms that round 2 replaced, so they do not meet the small-fix round, and round 3 is the limit. The reviewed tree is committed, and the defects go to the owner.

## Round 4 (owner decision of 2026-11-11, the two open defects only)

- Fixed: a command that the channel refuses (the network thread stopped) goes through `Input::settle_refused`: its send settles as `Failed`, so the composer keeps its text and edits again, an answered ask shows again, and the line says `the connection has stopped`. A refused `Follow` or `Saved` sets the same line.
- Fixed: a pending mark never leaves the map. At the bound, a failed mark leaves first (any session), then the oldest settled one. With 16 pending marks, `Input::answer` sends nothing, keeps the ask open, uses no send number, and the line is `16 requests are in flight` (`input::BUSY`, which `net` also gives for `Refusal::Busy`).
- Tests: `a_send_that_the_channel_refuses_settles_as_failed`, `an_answer_that_the_channel_refuses_shows_the_ask_again`, `a_command_with_no_send_that_the_channel_refuses_sets_the_notice`, `a_new_answer_is_refused_while_every_mark_is_pending`, `a_new_answer_drops_a_failed_mark_before_a_pending_one`, `a_new_answer_drops_a_settled_mark_before_a_pending_one`; `the_hidden_marks_are_bounded` follows the new order. `client-kit.md` Bounds rows updated. fmt, clippy, and 206 tests of the workspace pass.
