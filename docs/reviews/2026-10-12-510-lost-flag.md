# Review: the lost flag on a reused provider process (#510)

Scope: `ProviderConn.resumed`, `Records.resume_id/3`, the removal of `Turn.resumed`, and the rename of the stream event to `{:resume_id, id, cut}` and of the client event to `:resume_id` (`Helyx.Provider`, `Helyx.Event`, Core, the Claude Code and Codex providers, the TUI, two feature docs).

Invariant: the `lost` flag of a `:resume_id` event is true exactly for the first new resume id that a provider process sends, in a turn, after a start that passed a resume id. The turn that started the process can end before that. Entry points: `connect/1` in `TurnLoop` sets `ProviderConn.resumed`; `Records.resume_id/3` reads it and clears it. Documented exception: the names on disk (`harness_session`, `harness_session_id`, `lib/helyx/session/file.ex`).
