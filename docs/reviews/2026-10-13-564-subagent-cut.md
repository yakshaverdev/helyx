# Review: #564 A stopped sub-agent makes the next Claude Code cost unknown

Invariant: a Claude Code `result` with `terminal_reason` `aborted_tools`, while an `Agent` call since the previous `result` has no tool result or an `is_error` one, makes the cost of the next `done` nil. An `aborted_tools` with only other calls open keeps the cost known. The `Meter` reads every main-loop `assistant` and `user` line, also the lines of a program turn before the start of a Helyx turn's line.

Ticket text against the real shape: the ticket says "an `Agent` tool call of that turn has no tool result". Two new probes on 2.1.296 (research note, "An interrupt during a foreground sub-agent") show that the interrupt gives the open `Agent` call an `is_error` result before the `result`, as the run of 2026-09-29 also shows. So the literal rule never fires. The code reads "open" as no tool result or an `is_error` one. In both new runs the sub-agent calls that had ended were in the totals, so the flag was set where the cost was complete.

Accepted: an `Agent` call that failed by itself stays open, so a later interrupt of another call in the same program turn sets the flag: the cost shows as not known where it could be known. A background sub-agent that an interrupt stops does not set the flag (open, no ticket; not run). The `usage` of a `result` holds only the main loop's calls, so the token sums do not hold a sub-agent's tokens (observed in the two runs; no ticket).
