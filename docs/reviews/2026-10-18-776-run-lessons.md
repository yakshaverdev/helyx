## Round 1

Codex (`--base 8ed72721`): needs-attention, 1 high. The `/ship` command with a base reads only the commits from the merge base to `HEAD`, so a review before the commit gets none of the change inline. Reproduced: `collectReviewContext` of the companion script (1.0.6) gave 0 files with the base and the 3 changed files with `--scope working-tree`. The gap was there before this change too, with `origin/master` as the base.

Resolution: the `/ship` command uses the working tree scope with no base. The merge base stays for the bounds sensor (`git diff <base>` compares the working tree) and for the committed branch of the `/orchestrate` gate, where the script reads the commits from the merge base.

## Round 2

Codex (`--scope working-tree`): needs-attention, 1 high. The standards and spec axes come from `/mattpocock-skills:code-review`, which captures `git diff <fixed-point>...HEAD` and stops on an empty diff (its `SKILL.md`, lines 21 and 23, version 1.3.1). That form reads only commits, so before the commit those axes get none of the change. Reproduced: the three-dot form gave 0 files, `git diff <base>` gave the 3 changed files. The gap was there before this change too.

Resolution: the second finding on one mechanism (the diff that a review reads), so the fix is the mechanism: one paragraph of `/ship` step 2 states that every review of the step reads `git diff <base>` and the untracked files, and that the agents of the code-review skill get that command in place of its own.

## Round 3

Codex (`--scope working-tree`): needs-attention, 1 high. In a rerun round, a fix that restores a file to `HEAD` drops that file from the working tree diff, so Codex does not see the removal against the pre-fix snapshot. Codex confirmed the state with its collector in memory.

Resolution: not a defect. The working tree scope still gives Codex the whole final change against `HEAD`, a superset of the fix, so no changed code is out of its view; only the removed hunk is, and the spec and failure-path agents read it in `git diff <snapshot>`. It is an accepted hole, stated in `/ship`. The real part was a wording conflict: step 2 said that every review reads `git diff <base>`. It now says every review agent and the bounds sensor, and the Codex paragraph states its own diff. Round 3 reproduced no defect in the text, so the loop ended.
