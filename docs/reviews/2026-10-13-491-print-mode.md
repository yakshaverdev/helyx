# Review: #491 Print mode

Invariant: print mode (`-p` of `CodingAgent.CLI`, run by `CodingAgent.Print` as a client of one session) writes only the text of the last assistant message of the turn to stdout, and every other line (session id, notices, errors, logs) to stderr; each line of print mode (not the log lines) goes through the clean pass and the 4,000-byte cap. It reads piped stdin as raw bytes, up to 1 MiB of valid UTF-8, and fails with status 1 over that bound before any application starts. It exits 0 on a normal end, 1 on a failed or aborted turn, a stopped session, or an answer cut at `:max_tokens` (the text is still printed). The first SIGTERM or SIGHUP gives 143 or 129 after the turn is aborted and Core with the provider process stops, whatever blocks: the stdin read, the start of Core (then no prompt is sent), the turn, or the answer write to a full pipe. Since round 3 (owner decision): a SIGTERM or SIGHUP ends the run with 143 or 129 within the stated bound (`abort_ms/0`, 3,000 ms, plus the halt), whatever state stdout, stderr, and stdin are in.

Accepted holes (feature doc): a stdin pipe that stays open waits until a signal; the answer reaches stdout with no clean pass; SIGINT keeps the BEAM default; a signal after the run returns is dropped; a refusal exits 0 with a stderr line (worker decision); `mix helyx` prints its own compile output on stdout when the source changed. Core gets no print-mode code.
