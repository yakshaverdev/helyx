# Review of `--help` and `/help` (#696)

The change: `helyx --help` (and `-h`) prints the usage, one line for each switch, and the exit statuses, and returns 0 before any application starts. `/help` in the TUI adds one notice cell with the usage of each slash command and the keys, and starts no turn. The switch list, the command list, and the key list are each named once.

## Simplify

Four agents (reuse, simplification, efficiency, altitude).

| Finding | Resolution |
|---|---|
| `parse/1` named the commands that take no argument in its own list, apart from `@commands` | derived: `@bare` holds each command whose usage is its name alone |
| `types/0` built the OptionParser types on each parse | a module attribute, `@types`, next to `@forms` |
| The alias texts `(--print)` and `(-h)` repeat the `aliases:` keyword | skipped: a fourth tuple field for two switches |
| The regex of `parse/1` now compiles at runtime (about 4.7 µs, once per Enter) | skipped: a second literal list of names costs more than it saves |
| The exit statuses in the help repeat `@statuses` of `CodingAgent.Print` | skipped: a public accessor for two fixed numbers |

## Accepted holes

- The help is a notice cell, drawn red as `✕ <text>`, as the ticket says. An information cell would join the next information cells on one row.
- A parse error still wins over `--help`, as it does over `--version`: `helyx --help --bogus` prints the error and returns 1.
- The alias texts in the help lines are written by hand next to `aliases: [p: :print, h: :help]`.

## Merge gate (orchestrator)

- The help is now an information cell (`ViewModel.info/2`, dim), not a red notice: help is not an error. Accepted hole: an information cell that comes right after the help joins its last row, as consecutive information cells do.
