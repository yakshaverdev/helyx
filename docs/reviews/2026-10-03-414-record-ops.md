# Review: semantic record operations; callers stop pairing appends with events (#414)

Date: 2026-10-03. Base: `9b4ed8c`. Scope: `lib/helyx/session/server.ex`, `server/messages.ex`, `server/record.ex`, `server/wait.ex`, `long-lived-harness.md`, `session-snapshot.md`.

## Invariant

`Helyx.Session.Server.Messages` is the only writer of `transcript`, `file`, `model`, `provider`, and `resume_ids`, and each of its operations (`append_user`, `delta`, `end_assistant`, `tool_result`, `take_steer`, `end_turn`, `close_turn`, `set_model`, `resume`, called from `Server`, `Wait`, `Steering`, and `TurnLoop`) changes the open message, the transcript, and the session file and emits its events together, with the same events in the same order, the same persistence and disk failure notice, the same 8 MiB bound with its generic `stop_provider` path, and the same atomic subscribe and snapshot as master; open calls stay derived from the transcript, and no message goes between a call and its result. Accepted holes, as on master: the transcript append is O(n), and the transcript has no length bound.
