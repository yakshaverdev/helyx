## Round 1 (full)

- Simplify: removed a new module `Helyx.Hub.ScheduleAccess`; the list goes through `Access.list/3`, and the API sits in `Helyx.Hub.Api` beside `start_session/3` and `authorize/4`. It also restored the existence check of the wire list (`found/2`, not `exists?/2`, which also asks for a running session).
- Codex, failure path, standards, spec: `delete_schedule/3` called the Hub without `safe/1`, so an exit of the Hub call (a stalled or dead Hub after `:authority`) crashed the caller, not `{:error, :timeout}` as the spec states. Reproduced with `:erlang.suspend_process/1`. Fixed; test: the last test of `hub/schedules_test.exs` (the Hub stopped after `:authority`).
- Spec: the `schedule_list` result could pass `Helyx.Message.max_result_bytes/0`: 256 schedules (the user cap) at about 370 bytes a line, and Core would keep only the head and the tail. Fixed: the lines stop at 60,000 bytes, and a last line counts the rest and points to the list of one session (at most 16 schedules). Test: "stays under the result bound at the cap of a user".
- Spec, standards: the coordinator system prompt named five tools, so the model did not know the two new ones. Fixed, with a test that the prompt names all seven.
- Spec: the list showed no outcome of the last run, which `hub.md` (decisions 11 and 12) says the user reads there. Fixed: `last run <outcome> at <time>`. Test: "shows the last outcome of a schedule".
- Standards: a guard and a fallback clause for arguments that are not a map, which `Helyx.Session.Stream.check/1` proves: removed. The error text for an unknown key now names the cause. Bounds rows for both tools added to `coordinator.md`.
- Standards: `Access.list/3` sits among private clauses. Not changed: it sits beside the wire clause that uses it.

## Round 2 (reduced)

- Failure path: a prompt with a control byte showed as a cut list of byte numbers (`inspect/1` of a binary that is not printable), so the model lost the prompt. Reproduced through `Hub.schedule/3`. Fixed: `inspect(prompt, binaries: :as_strings)`. Test: "shows a prompt with a control byte as escaped text"; the bound test now asserts the escaped form.
- Spec: the tool description did not name the outcome; fixed.
- Spec, not changed: `Helyx.Hub.schedule/3` (from #870) also lets an exit of a Hub call escape. It is not in this diff; it is reported to the owner.
- Spec, not changed: an ended recurring schedule still prints its `at` and period; the line says `ended` and the last outcome, so it reads as ended.

## Round 3 (reduced)

- Failure path: a prompt over 256 bytes was cut with no mark, so the model could not tell it from a whole prompt. Reproduced. Spec: no findings.
